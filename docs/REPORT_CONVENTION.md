# 제출용 보고서 작성 규칙 (REPORT_CONVENTION)

제출용 문서(`outputs/reports/final_report.md` 및 향후 외부 제출물)를 쓰거나 고칠 때 적용하는
규칙이다. **내부 문서에는 적용하지 않는다** — `decision_log.md`·`*_kgj.md` 등 검증 기록은
과정을 남기는 것이 목적이라 이 규칙의 반대가 옳다. 즉 이 규칙은 "내부 기록을 제출물로
승격할 때 반드시 거치는 번역 규칙"이다.

> 배경: 최종 보고서 초안이 "보고서가 아니라 의사결정 일지"라는 피드백을 받았다(2026-07-31).
> 내용·엄밀성·재현성은 문제가 아니었고, **서술의 시점과 장르**가 문제였다. 아래 규칙은 그
> 피드백 6개 항목을 실행 가능한 형태로 옮긴 것이다.

---

## 규칙 0 — 독자 규정 (모든 규칙의 기준)

독자는 **프로젝트를 처음 접하는 심사자**다. 통계·금융 지식은 있으나, 팀의 회의·이슈·작업
이력·내부 파이프라인에 대해서는 아무것도 모른다.

문장을 쓰기 전에 한 가지만 자문한다:

> **이 문장은 "우리가 무엇을 어떻게 했는가"를 기술하는가,
> 아니면 "우리가 어떻게 그 결정에 도달했는가"를 기술하는가?**

전자만 본문에 남긴다. 후자(검토·기각·논쟁·확정의 연대기)는 내부 문서의 몫이고, 제출물에는
채택 근거로 압축되거나 부록으로 간다.

---

## 규칙 1 — 채택한 방법 먼저, 결정 서사 금지

- 각 절의 첫 문단은 **채택한 방법의 기술**로 시작한다. "후보 검토 → 실측 → 기각/채택"
  순서의 작업 서사로 절을 구성하지 않는다.
- 기각한 대안은 두 단계로 처리한다:
  1. 채택 근거를 강화할 때만 본문에 **1~2문장**으로 남긴다 (수치 근거 포함 가능).
  2. 그 이상의 검토 기록은 **부록 「대안 검토 요약」 표**(대안 / 결과 / 판단 근거 1줄)로
     옮긴다. **삭제가 아니라 이동이다** — 수치·검증 정보는 보존한다.
- "시도했으나 채택하지 않은 것"을 절 제목·절 단위로 다루지 않는다. 미사용 항목은
  한계 절의 한 문단 + 부록 한 행이면 충분하다.
- "확정했다 / 기각했다 / 채택했다 / 폐기했다" 같은 **의사결정 동사를 방법 기술에 쓰지
  않는다** — "사용한다 / 사용하지 않는다 / ~로 정의한다"로 쓴다.

**예시 (실제 초안 문장):**

| Before (결정 서사) | After (방법 기술) |
| --- | --- |
| "36/60개월 분리 모형은 실측으로 기각, 통합 모형 + `term` 피처를 채택했다." | "만기는 별도 모형으로 나누지 않고, 통합 모형에 `term`을 설명변수로 투입한다. 만기별 분리 모형은 60개월 표본이 약 8만 건으로 줄어 판별력이 오히려 낮아진다(AUC −0.006)." |
| "시간순 분할 대안도 실측으로 기각했다" | "분할은 층화 랜덤 방식이다. 시간순 분할은 2015-12부터 수집된 변수 14개가 Train에서 전부 결측이 되어 사용할 수 없고, 그 목적(낙관적 평가 방지)은 만기 필터가 이미 달성한다." |
| 절 제목 "2.5 거시경제지표 — 시도했으나 채택하지 않은 이유" | 한계 절의 한 문단 "거시경제 변수는 사용하지 않았다. 표본 기간이 경기 회복기에 집중되어(corr(실업률, 발행연도) = −0.911) …" + 부록 표 1행 |

## 규칙 2 — 내부 작업 식별자 제거

본문·그림 캡션·표에서 다음을 쓰지 않는다:

- 이슈·결정 번호: `#20`, `#21 ②`, `#23 B` 등
- 내부 문서·파이프라인 참조: `decision_log`, "6:2:2 분할 산출물", "본실행", "핸드오프",
  "B팀", 팀원 이니셜(`_kgj` 등)
- 스크립트 파일명 (`oof_diagnostics.py` 등) — **부록 A(재현 가이드)·부록 B(코드 색인)에서만**
  허용한다.

그림 캡션은 **그 그림이 무엇을 보여주고 어떻게 읽는지**만 적는다: 데이터 표본, 축의 의미,
읽는 법. 산출 단계·산출 스크립트·이슈 번호는 캡션에 넣지 않는다. 최종 수치와 다른 설정의
그림이면 "예비 분석 결과이며 최종 수치와 설정이 다르다" 수준으로만 밝힌다.

## 규칙 3 — 가상의 논쟁 상대 금지

작업 중 실제로 오갔던 반론·논쟁을 향해 방어하는 문장을 쓰지 않는다. 처음 읽는 독자에게는
존재하지 않는 논쟁이다. 반박이 담고 있던 **근거만 긍정문으로** 남긴다.

금지 패턴: 따옴표 반론 인용 + 반박 ("…라는 반론에는 …로 답한다"), "…라는 직관은 실측으로
반증됐다", "… 논쟁이 겨눈 대상".

**예시:**

| Before | After |
| --- | --- |
| ""LC 등급을 그대로 베끼는 것 아닌가"라는 반론에는 위 관점으로 답한다" | "본 연구의 의사결정 주체는 LC 심사를 통과한 대출에 투자할지 결정하는 투자자이므로, LC의 심사 결과(등급·금리)를 포함해 승인 시점에 관측 가능한 모든 정보를 설명변수로 사용한다." |
| ""단조변환이라 경계가 안 바뀐다"는 직관은 실측으로 반증됐다" | "isotonic 회귀는 계단함수여서 예측값의 고유값 수를 크게 줄이므로(42.9만 → 127개), 보정 후 확률로 분위를 나누면 칸 인원이 최대 2.10%p 치우친다. 따라서 분위 경계는 보정 전 확률로 계산한다." |

## 규칙 4 — 문체: 격식 있는 산문

- **이모지·경고 기호(⚠️·✅·❌) 금지.** 강조가 필요하면 문장 구조로 해결한다.
- **구어·은유·수사 표현 금지.** 발견되는 대로 아래 대응표에 추가한다:

| 쓰지 않는다 | 대신 쓴다 |
| --- | --- |
| 함정이 있다 | 주의가 필요하다 / ~한 문제가 있다 |
| 셀 표본이 (급격히) 마른다 | 셀 표본 수가 크게 감소한다 |
| 변수 블록이 통째로 죽는다 | 해당 변수들이 전부 결측이 되어 사용할 수 없다 |
| (그룹 평균으로) 뭉갠다 | 평균으로 대체하여 개별 정보를 잃는다 |
| 상수로 박는다 | 상수로 고정한다 |
| 분할 운 / 표본 운 | 분할(표본)에 따른 우연 변동 |
| 치른 대가 | 이 선택의 비용 / 부작용 |
| 잡음을 해상도를 주는 척하며 배분한다 | 잡음을 추정치에 배분할 뿐 정보를 더하지 않는다 |
| 헤드라인 | 주 성과지표 / 주 보고 지표 |
| 의도된 정직화 | 측정 방식을 정확하게 바꾼 데 따른 효과 |
| 방어 불가능하다 | 타당하지 않다 / 정당화되지 않는다 |
| 금지선이다 | 본 연구의 평가 원칙상 허용되지 않는다 |
| 깨끗하다 (일반화 판정 등) | 이상이 발견되지 않았다 / 기준을 충족한다 |

- **제목은 중립적 명사구**로 쓴다. 판정·수사가 들어간 제목("일반화 판정 — 세 겹으로
  깨끗하다")은 쓰지 않는다("일반화 성능 확인" 등).

## 규칙 5 — 설득이 아니라 서술

- **볼드는 두 용도로만**: ① 핵심 결과 수치의 첫 제시 ② 용어의 최초 정의. 문장 단위 강조용
  볼드는 쓰지 않는다. 결론의 정당성은 수치가 담보하며, 어조로 밀어붙이지 않는다.
- 규범적 단정("보정을 되돌리는 것은 과대추정의 부활이지 개선이 아니다")은 근거 서술로
  바꾼다("보정 전 기준은 정상상환 수익률을 36개월 +1.06%p, 60개월 +2.24%p 과대추정한다").
- 같은 주장을 반복하지 않는다. 한 번 수치로 보였으면 끝이다.

---

## 규칙 6 — 문단이 본문의 기본 단위

- 본문은 **완결된 문장으로 이루어진 문단**으로 쓴다. 불릿은 대등한 항목 3개 이상을
  열거할 때만 쓰고, 논증의 전개를 불릿으로 대체하지 않는다.
- **"—" 뒤에 부연을 다는 패턴을 쓰지 않는다.** 문장을 나누거나 종속절로 풀어 쓴다.
  ("—"는 범위·수식 표기 등 관례적 용법만 남긴다.)
- **"→"는 코드 블록·수식 안에서만** 쓴다. 본문 산문에서 인과·순서를 화살표로 잇지 않는다.
- 주어는 "우리"·"팀"이 아니라 **"본 연구"** 또는 무주어 서술을 쓴다.

## 규칙 7 — 정보 보존

이 규칙들은 서술의 층위를 바꾸는 것이지 내용을 줄이는 것이 아니다. 본문에서 밀려난
기각 근거·실측 수치·검증 기록은 부록 「대안 검토 요약」 표와 내부 문서 참조(부록 A)에
보존한다. **수치·재현성 정보를 지우는 방식의 "정리"는 하지 않는다.**

## 제출 전 점검 체크리스트

기계 점검 (저장소 루트에서, 대상 파일에 대해):

```bash
F=outputs/reports/final_report.md
grep -nE '#[0-9]+' $F                       # 이슈 번호 → 0건 (마크다운 헤더 # 제외)
grep -nE '⚠️|✅|❌|→' $F                     # 이모지·화살표 → 코드/수식 블록 외 0건
grep -nE '반론|직관은|논쟁' $F                # 가상 논쟁 패턴 → 0건
grep -nE '함정|말라|죽는|뭉개|박지 않|헤드라인|금지선|방어 불가|정직화|운\b|대가' $F
                                             # 금칙어 → 0건 (대응표 참조)
grep -nE 'decision_log|_kgj|본실행|핸드오프|[0-9]:[0-9]:?[0-9]? 분할 산출물' $F
                                             # 내부 참조 → 0건
```

눈으로 점검:

- [ ] 각 절의 첫 문단이 "채택한 방법"으로 시작하는가 (검토 서사로 시작하지 않는가)
- [ ] 기각 대안이 본문에 2문장을 넘겨 남아 있지 않은가 (넘치면 부록으로)
- [ ] 그림 캡션에 산출 단계·스크립트명·이슈 번호가 없는가
- [ ] 볼드가 수치 첫 제시·용어 정의 외에 쓰이지 않았는가
- [ ] 불릿이 논증 전개를 대체한 곳이 없는가 ("—" 부연 연쇄 포함)
- [ ] 스크립트 파일명이 부록 밖에 등장하지 않는가
