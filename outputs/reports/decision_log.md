# 보고서 작성 흐름 (Decision Log)

이 문서는 최종 보고서를 쓰기 위해 팀이 논의·결정한 과정을 주제별로 기록한 작업 로그다. 최종 보고서 각 장은 여기 기록된 배경·결정·근거를 그대로 확장해서 작성한다. 날짜는 결정이 확정된 시점 기준(대부분 2026-07-22 논의).

## 보고서 목차(안)

1. 프로젝트 개요 및 목적 (Sharpe Ratio 극대화 framing)
2. 데이터 및 전처리
   - 2.1 변수 사전/사후(pre/post-approval) 구분
   - 2.2 결측치 처리, 파생변수, 컬럼 표준화
   - 2.3 거시경제지표 추가
3. 신용평가모형 후보 비교 및 선정
4. 부도 손실 정의 — IRR 근사
5. Sharpe Ratio 기반 threshold 결정 및 안정성 검증
6. 최종 결과 (Test set 검증, Approve-all 등 벤치마크 비교)
7. 한계 및 향후 과제

### 3. 신용평가모형 후보 비교 — 진행 중
- **배경**: 참고논문은 모형 비교 없이 XGBoost 단일 모델만 사용, 방법론의 초점은 "모델 선택"이 아니라 "예측확률→threshold 연결"에 있었음(AUC-Sharpe 상관계수 0.228로 약함, 논문이 직접 제시).

- **잠정 방향**: 로지스틱(해석·보정 용이, 베이스라인) + GBM(성능, 메인 후보) 병행 비교. 딥러닝은 이 데이터 규모에서 우위 불확실 → 우선순위 낮음.
- **남은 판단**: 로지스틱 vs GBM 중 최종 1개 확정 여부, GBM 채택 시 확률보정(Platt/isotonic) 방법 선택.

### 4. 부도 손실 정의 — IRR 근사 — 방법론 확정, 적용 범위 미확정
- **배경**: 기존 가정(부도 시 실현수익률 = -100%)이 실제 회수율(Charged Off 217,366건 평균 -45.19%, 중앙값 -49.00%)과 괴리 → 부도손실 과대평가로 Sharpe·threshold 전체 왜곡 우려.
- **결정 1**: 정상상환·조기상환 대출은 상각형 대출 특성상 IRR이 수학적으로 정확히 `int_rate`와 같음(NPV 논리로 증명) → 재구성 불필요, `int_rate` 그대로 사용.
- **결정 2**: 부도 대출만 3단계 현금흐름(정상납입 구간 → 연체·미상환 구간 → recoveries 일시회수)으로 근사 재구성.
- **결정 3**: 연율화는 월별 현금흐름 직접 계산 + 단순 ×12 관례 채택 (`int_rate` 정의 방식과 일치, 복리연율화·HPR방식은 기각 — HPR방식은 참고논문이 쓰는 방식이나 분할상환 구조에서 수익률을 구조적으로 낮추는 오류가 있어 제외).
- **남은 판단**: 부도 건별 IRR 근사 계산 vs (지난 TA 질문에서 제안된) grade×term 평균 실현수익률 대체 — 팀 트레이드오프 판단 필요. 투자자 서비스수수료(~1%) 반영 방식도 별도 결정 필요.
- **정정 기록 (2026-07-29)**: **베이스라인 표기**가 문서마다 어긋나 있던 것을 **-100%로 통일**했다. (베이스라인을 통일했다는 뜻이며, **부도 시 실현수익률의 최종 정의는 여전히 미확정**이다 — 위 "남은 판단"과 #5 참조.) `README.md`·`docs/architecture.md`·`src/analysis/AGENTS.md`는 "부도 시 0", 본 항목 #5는 "0 가정"으로 적고 있었으나, 실제 초기 가정은 **-100%(원금 전액 손실)** 이 맞다. "0"은 **회수액이 0**이라는 뜻의 축약 표기가 수익률로 오독된 것이다. 수익률 0%는 "원금 전액 회수, 이자만 손실"이라는 전혀 다른 가정이고, 이대로 두면 위 배경의 논증 방향(과대평가 ↔ 과소평가)이 반대로 뒤집힌다. 네 문서를 모두 정정했다.
  - 참고로 세 가정의 차이는 작지 않다. 부도율 20%·`int_rate` 12%·Rf 2%인 단순 포트폴리오 기준: 부도 시 0% → 평균 9.60%/Sharpe **+1.58**, -45.19% → 평균 0.56%/Sharpe **−0.06**, -100% → 평균 −10.40%/Sharpe **−0.28**. 부호까지 바뀌며, 최적 threshold 위치도 함께 이동한다.

### 5. 종속변수 설정에 따른 모델 프레이밍 정리 — 방법론 정리, 팀 확정 필요
- **배경**: 신용평가모형의 종속변수를 `loan_status`(이진분류), `IRR`(회귀), `Sharpe Ratio`(포트폴리오 통계량) 중 무엇으로 둘지에 따라 적용 가능한 모델이 달라짐 → 세 경우를 정리.
- **정리 1 — `loan_status` (이진분류)**: 후보는 기존 #3 항목과 동일(로지스틱/RF/GBM/MLP/Cox PH). Validation의 부도확률(PD) 산출용.
- **정리 2 — `IRR` (회귀)**: 정상상환·조기상환 대출은 IRR = `int_rate`로 결정론적(#4에서 이미 증명)이므로 순수 회귀보다 **2단계(hurdle) 모형**이 적합.
  - 1단계: 부도확률 `P(default)` 분류 (#3 후보 모델 재사용).
  - 2단계: **부도 서브셋만** 별도로 손실크기(`IRR|부도`) 회귀 (RF/GBM 회귀, 극단값 대응 위해 필요 시 Huber/quantile loss).
  - 결합: `E[IRR] = P(정상)×int_rate + P(부도)×E[IRR|부도]`.
  - **주의(leakage)**: `int_rate`를 사전 변수로 재분류하기로 했으므로(#1), IRR 전체를 한 번에 회귀하면 정상상환 건에서 `int_rate`가 사실상 정답을 그대로 피처로 넣는 셈이 됨 → 2단계 모형에서 부도 서브셋만 회귀하면 이 문제가 자연히 해소됨.
- **정리 3 — `Sharpe Ratio` 자체를 종속변수로**: 개별 대출 단위 라벨이 아니라 여러 대출에 걸친 집합 통계량이라 지도학습 종속변수로 직접 쓸 수 없음. 실질적으로는 위 1·2단계 산출물(PD 또는 `E[IRR]`)을 입력으로 Validation set에서 threshold를 바꿔가며 Sharpe를 계산하는 **결정(정책 최적화) 단계**로 처리 — 별도 모델이 아니라 TOC 5장(Sharpe 기반 threshold 결정)의 대상.
- **남은 판단**: PD 단독 threshold(기존 방식, 부도 시 실현수익률 **-100%** 가정) vs `E[IRR]` 기반 threshold(위 2단계 모형, 부도 시 실제 근사손실 반영) 중 어느 쪽으로 최종 Sharpe 최적화를 수행할지 팀 확정 필요. 후자가 #4의 IRR 근사 방법론과 정합적이나 구현 비용이 더 큼.

### 6. 2단계(Hurdle) 모형 구조 및 단계별 추천 모델 — 방법론 정리, 팀 협의 필요
- **배경**: #5에서 정리한 "`E[IRR]` 기반 threshold" 방향을 구체적인 파이프라인 구조로 정리. **아직 팀이 확정한 결정이 아니라 제안 단계이며, 채택 여부와 세부 모델 선택은 팀 협의로 확정해야 함.**

- **구조 (1단계 → 2단계 → 결합 → threshold 결정 → 검증)**

```
[전체 대출 데이터]
       │
       ▼
┌─────────────────────┐
│ 1단계: 분류모델        │  종속변수 = loan_status (Fully Paid vs Charged Off)
│ P(정상), P(부도) 산출  │
└─────────────────────┘
       │
       ├── 정상상환 예측분 ──→ IRR = int_rate (결정론적, #4에서 증명 → 회귀 불필요)
       │
       └── 부도 예측분(서브셋)만 추출
                │
                ▼
       ┌─────────────────────┐
       │ 2단계: 회귀모델        │  종속변수 = IRR (부도 대출만, #4의 3단계 현금흐름 근사값)
       │ E[IRR|부도] 산출      │
       └─────────────────────┘
                │
                ▼
       ┌─────────────────────────────────────┐
       │ 결합: E[IRR] = P(정상)×int_rate       │
       │            + P(부도)×E[IRR|부도]      │
       └─────────────────────────────────────┘
                │
                ▼
       ┌─────────────────────────────┐
       │ 3단계: threshold 최적화        │  (모델 아님, 그리드서치)
       │ Validation set에서 E[IRR]     │
       │ 컷오프별 Sharpe 계산 → argmax  │
       └─────────────────────────────┘
                │
                ▼
       Train 전체 재학습 → Test set 1회 검증 (재조정 없음, AGENTS.md 규칙)
```

- **단계별 추천 모델 (제안, 팀 협의 필요)**
  - **1단계(분류)**: GBM(LightGBM/XGBoost) + 확률보정(Platt/isotonic)을 메인 후보로, 로지스틱회귀를 해석용 베이스라인으로 병행(#3 기존 방향과 동일). GBM 확률은 과신되는 경향이 있어 보정 없이 쓰면 위험.
  - **2단계(회귀)**: GBM 회귀(LightGBM/XGBoost) + Huber/quantile loss를 메인 후보로. 대안으로 grade×term 그룹 평균 실현수익률(#4의 기존 "남은 판단"과 동일 쟁점)과 성능·안정성 비교 필요 — 부도 손실은 개별 피처보다 회수 프로세스 노이즈 비중이 커서 개별 회귀의 신호 대비 잡음이 낮을 수 있음.
  - **3단계(threshold)**: 별도 모델 아님. 1차원 그리드서치(필요 시 이분탐색). AGENTS.md 규칙대로 `random_state` 0~29 반복으로 안정성 검증.

- **주의(leakage, #5 재확인)**: `int_rate`는 사전 변수로 재분류됨(#1) → 2단계 회귀는 반드시 부도 서브셋만 사용해야 함. 전체 대출을 한 번에 회귀하면 정상상환 건에서 `int_rate`가 정답을 그대로 피처로 넣는 셈이 되어 leakage 발생.

- **팀 협의 필요 사항**:
  - PD 단독 threshold(#5에서 언급한 기존 AGENTS.md 방식) vs `E[IRR]` 기반 threshold 중 최종 채택 여부.
  - 1단계 로지스틱 vs GBM 최종 1개 확정(#3과 동일 쟁점).
  - 2단계 개별 IRR 회귀 vs grade×term 평균 대체 여부(#4와 동일 쟁점).
  - 확률보정 방법(Platt vs isotonic) 선택.

### 7. 1단계·2단계 모델 상세 비교 — 로지스틱 vs GBM+보정(1단계), RF vs GBM(2단계)
- **배경**: #6 추천안의 근거를 구체화. 최종 모델 선택 전 팀이 참고할 트레이드오프 정리(확정 아님).

- **1단계 — 로지스틱 회귀 vs GBM + 확률보정**:
  - 로지스틱: 선형(로그오즈) 관계만 포착 → 상호작용 놓칠 수 있어 AUC는 대체로 GBM보다 낮음. 대신 MLE로 log-loss를 직접 최적화해 확률이 원래 잘 보정되는 경향(별도 보정 단계 대체로 불필요), 계수가 오즈비로 직접 해석 가능, 구현·튜닝 리스크 낮음.
  - GBM+보정: 비선형·상호작용을 포착해 AUC는 더 높은 경향이나, 부스팅 특유로 확률이 0/1로 쏠리는 과신 경향 → Platt/isotonic 보정이 필수(보정용 별도 held-out fold 필요, 보정 자체도 과적합 가능 → 구현 리스크 추가).
  - 이 프로젝트 특이사항: 참고논문의 AUC-Sharpe 상관계수 0.228(약함) → GBM의 AUC 우위가 실제 Sharpe 개선으로 이어질 거란 보장이 약함. 반면 확률보정 오류는 `E[IRR] = P(정상)×int_rate + P(부도)×E[IRR|부도]` 식에 직접 들어가 threshold를 왜곡시키므로(과신된 `P(부도)`를 그대로 쓰면 `E[IRR]`이 실제보다 과소 추정됨), GBM 채택 시 보정 품질이 성능 우위보다 더 중요할 수 있음.

- **2단계 — Random Forest 회귀 vs GBM 회귀**:
  - RF(배깅): 트리를 독립적으로 병렬 학습 후 평균 → 분산 감소에 강함, 노이즈·극단값(완전손실 등)에 상대적으로 견고, 튜닝 부담 낮음. 원시 성능은 GBM보다 대체로 낮음.
  - GBM(부스팅): 잔차를 순차 보정 → 편향 감소에 강해 정교하게 튜닝하면 성능 상한이 더 높음. 다만 잔차가 큰 샘플(극단값)에 다음 라운드가 과도하게 집중하는 경향 → Huber/quantile loss 없이는 과적합 위험, 튜닝 난이도·구현 리스크 높음.
  - 판단 기준: 부도 손실(severity)은 회수 프로세스·타이밍 등 관측되지 않는 요인 영향이 커 노이즈가 많은 타겟일 가능성 → 이 경우 분산을 눌러주는 RF가 실전에서 더 안정적일 수 있음. GBM은 outlier 처리(Huber loss)를 제대로 튜닝할 여력이 있을 때 우위.

- **결론(잠정, 팀 확정 필요)**: "이론적 성능 상한"은 두 단계 모두 GBM이 높지만, 이 데이터 특성(노이즈 많은 severity, 목적함수가 AUC가 아닌 Sharpe)과 프로젝트 시간 제약을 고려하면 RF·로지스틱의 "구현 리스크 낮음·안정성" 이점이 실질적으로 클 수 있음. #6의 "팀 협의 필요 사항"과 동일한 쟁점이므로 별도 판단 목록 추가 없이 그 항목으로 최종 확정.

### 8. 전처리 파이프라인 구조 및 모델 조합(GBM+GBM / GBM+RF) 압축안 — 제안, 팀 협의 필요
- **배경**: #6·#7에서 1단계(Logistic vs GBM) × 2단계(RF vs GBM) 총 4개 조합((a) GBM+GBM, (b) Logistic+GBM, (c) GBM+RF, (d) Logistic+RF)을 검토했음. 조합마다 요구하는 독립변수 전처리(결측치 처리, 범주형 인코딩, 스케일링, 다중공선성 체크)가 달라, 4개를 모두 병행하면 전처리 브랜치가 최대 3개까지 늘어나 시간 제약상 부담. **아직 팀이 논의·확정한 내용이 아니라 AI(Claude Code)와의 대화에서 정리한 제안이며, 채택 여부는 팀 협의로 확정해야 함.**
- **모델별 전처리 민감도 비교**:
  - GBM(LightGBM/XGBoost): 결측치 native 처리, 범주형 native 처리, 스케일링 불필요, 다중공선성 무관.
  - Random Forest(sklearn): 결측치·범주형 명시적 처리 필요(대체+인코딩), 스케일링 불필요, 다중공선성 무관.
  - Logistic: 결측치·범주형 명시적 처리 + 스케일링 필수 + 이상치/로그변환 판단 + VIF 등 다중공선성 체크까지 필요 — 세 모델 중 가장 무거운 브랜치.
- **1단계·2단계 전처리 일관성 원칙**: 결측치 대체값·인코딩 매핑·스케일러 파라미터는 Train 전체(정상+부도 포함)에서 한 번만 fit하고, 1단계 전체 데이터와 2단계 부도 서브셋 양쪽에 동일하게 transform만 적용한다. 부도 서브셋으로 별도 재fit 금지 — 표본이 작아 통계량이 불안정해질 뿐 아니라, 같은 대출이 단계별로 다른 값으로 표현되는 불일치가 생김(Test로 모형·threshold를 재조정하지 않는다는 AGENTS.md 원칙과 같은 논리). target encoding처럼 타겟에 의존하는 인코딩은 1·2단계 타겟이 다르므로(`loan_status` vs `IRR`) 사용하지 않는다.
- **베이스 테이블 설계**: 공통으로 거치는 전처리는 최소화한다 — `loan_status`가 `Current`인 행 제외, 사후(post-approval) 변수 제외까지만 공통 처리. 그 외 결측치 대체·인코딩·스케일링·이상치 처리는 채택된 모델 조합별 브랜치에서 각자 진행한다(GBM native 기능을 희생하는 "최소공통분모" 방식은 채택하지 않음 — 조합별 성능 상한을 우선).
- **제안**: 시간 제약을 고려해 4개 조합 중 **(a) GBM+GBM**, **(c) GBM+RF** 두 가지로 좁히는 안.
- **근거**: (a)는 GBM-native 브랜치 하나만 있으면 되고, (c)의 2단계(RF)는 그 브랜치 위에 "결측치 대체+인코딩"만 추가하면 되어 스케일링·VIF를 건너뜀 — GBM-native 브랜치의 경량 확장에 가까움. 반면 (b) Logistic+GBM은 Logistic 전용 브랜치(대체+인코딩+이상치변환+스케일링+VIF)를 통째로 새로 구축해야 하고, 특히 VIF 체크는 거시지표 매칭 방식이 아직 미확정(#2)이라 반복 작업이 될 위험이 커 시간 대비 부담이 가장 크다고 판단.
- **트레이드오프(인지된 리스크)**: 이 안대로 가면 #7에서 제기된 "1단계 Logistic vs GBM — 참고논문 AUC-Sharpe 상관계수(0.228, 약함)가 이 프로젝트에서도 재현되는지" 질문은 이번 라운드에서 검증하지 못한다. 시간이 남으면 (b) 또는 (d) 추가 검토 여지를 남겨둠.
- **팀 협의 필요 사항**: (a)+(c) 압축안 채택 여부, 또는 성능 검증 가치가 더 크다고 판단되면 (b)를 포함하는 대안 검토.

- **② 만기도래를 요구하는 것 자체는 타당하다**: 팀 분할 규칙이 **랜덤 6:2:2**(`src/analysis/AGENTS.md`, `README.md`)이므로 Test set에도 같은 편향이 그대로 섞여 들어간다 — 검증 단계가 이 편향을 잡아주지 못하므로 **표본 필터가 유일한 방어선**이다. IRR/실현수익률(#4)도 완결된 현금흐름을 요구한다(유지되는 완결건 중 `out_prncp` > 0 = 0건).
- **③ 연도 컷은 과보수적 — 「만기 + 버퍼 6개월」로 바꿀 것을 권고**: 연도 컷은 이미 만기가 도래한 **187,821건**(36m 2017년 128,435 + 60m 2015년 59,386, 부도율 21.17%)을 발행연도라는 이유만으로 버린다. 조건을 `issue_d + term ≤ 2020-04`로 바꾸면 같은 청정도를 유지하면서 **+79,428건**을 회수한다. 버퍼 6개월은 상각(charge-off) 확정에 통상 4~5개월이 걸리기 때문이다.

  | 규칙 | 완결표본 | 구간 내 `Current` | T2 관측률 |
  | --- | ---: | ---: | ---: |
  | 현행(`Current`만 제외) | 1,117,571 | 35.2% | 54.4% |
  | 팀 결정(연도 컷) | 644,135 | 0.00% | 31.6% |
  | 만기 ≤ 2020-10 (버퍼 0) | 831,956 | 4.14% | 39.9% |
  | **만기 ≤ 2020-04 (버퍼 6m)** | **723,563** | **0.06%** | 35.8% |

- **④ T2 블록(14개)은 유지한다 — 잠정 삭제 권고를 철회**: 만기컷을 걸면 T2 관측률이 54.4% → 35.8%로 떨어지고 **60개월 구간에서는 0.0%** 가 된다(60m 만기도래 = 2015년 이전 발행 vs T2 수집 개시 2015-12, 구조적 배타). 관측률 붕괴만 보고 삭제를 권고했으나, 새 표본에서 기여도를 다시 재보니 **기여가 살아 있다.** 관측률이 떨어져도 관측된 행에서의 정보량은 그대로이기 때문이다.

  | 표본 | T2 관측률 | AUC(T2 포함) | AUC(T2 제외) | Δ | seed 편차 | 판정 |
  | --- | ---: | ---: | ---: | ---: | ---: | --- |
  | 현행(`Current`만 제외) | 54.5% | 0.69960 | 0.69214 | **−0.00746** | 0.00348 | 기여 있음 |
  | 만기+버퍼6m 전체 | 35.7% | 0.67633 | 0.67148 | **−0.00484** | 0.00196 | 기여 있음 |
  | 만기+버퍼6m **36m만** | 41.6% | 0.66955 | 0.66106 | **−0.00849** | 0.00148 | **기여 있음(최강)** |
  | 만기+버퍼6m **60m만** | 0.0% | 0.62278 | 0.62283 | +0.00005 | 0.00239 | 없음(변수 부재) |

  36m 분리 모형에서는 오히려 현행 표본보다 기여가 **커진다**(잡음의 5.7배). 60m에서 0인 것은 "T2가 쓸모없다"가 아니라 "그 구간엔 T2 값이 아예 존재하지 않는다"는 뜻이며, GBM은 전량 결측 컬럼을 자동으로 쓰지 않으므로 **삭제할 필요조차 없다.** → **T2 변수는 남기고, 없애야 할 것은 T2 *결측더미* 뿐이다**(#8의 GBM native 결측 처리 원칙과 동일한 결론).
- **⑤ term-vintage 교락이 새로 생긴다**: 만기를 요구하면 최근 연도에 36m만 남아 발행연도와 만기가 얽힌다. 팀 결정 기준 2015년 부도율은 14.89%인데 만기컷 기준으로는 18.90% — **4%p가 순전히 term 구성 차이**다. 60m 비중이 현행 25.1% → 팀 결정 12.0% / 만기+버퍼6m 13.9%로 줄어든다. 연도 컷 고유의 문제가 아니라 **만기를 요구하는 순간 생기는 대가**다. 완화책으로 **36m/60m 분리 모형**을 후보로 올렸으나(④에서 T2 기여가 36m에서 가장 크게 나온 것이 근거였다), **#13에서 실측한 결과 분리는 이득이 없고 60m에서 오히려 나빠져 통합 모형을 채택한다.** term-vintage 교락은 term을 피처로 투입하고 성능표를 term별로 나눠 보고하는 방식으로 다룬다.
- **⑥ 거시지표(#11) 재검토 필요**: 두 규칙 모두 발행연도 상한이 2017년이 되어 **2017~2020 구간(금리 인상기·COVID)이 표본에서 사라진다.** #11에서 이미 "표본 기간이 회복 일변도라 경기 순환의 양방향을 관측할 수 없다"가 반대 부호의 근본 원인으로 지목됐는데, 표본이 더 짧아지면 그 문제가 심해진다. #11의 팀 협의 5건은 이 표본 정의를 확정한 뒤 다시 판단해야 한다.
- **정정 기록**: 검토 과정에서 "out-of-time 검증 구간이 사라진다"를 문제로 올렸으나 **팀에는 시간 기준 분할 규칙이 없다** — 규칙은 랜덤 6:2:2다. out-of-time은 검증용 진단 도구일 뿐이므로 이 항목은 쟁점이 아니다. 오히려 랜덤 분할이라는 사실이 위 ②의 논거가 된다.
- **팀 협의 필요(2건)**: ① 연도 컷 vs 만기+버퍼 6개월 ② 표본 축소 후에도 거시지표를 쓸 것인지(#11과 함께 판단). *(기존 ②「36m/60m 분리 모형 채택 여부」는 #13에서 실측으로 종결)*


### 13. 모형 구성 확정 — 통합 모형·전 결측 NaN 유지 (2026-07-29)

- **상세 문서**: `outputs/reports/preprocessing_crosscheck_kgj.md` (팀원 4인 검증문서 교차검증판) 6·8절
- **재현**: `src/analysis/term_split_comparison.py`, `src/analysis/missing_scheme_comparison.py`
  (결과표 `outputs/term_split_comparison.csv`, `outputs/missing_scheme_comparison.csv`)
- **전제**: 이 항목의 결론은 **① 모형을 XGBoost로 단일화(로지스틱 폐기) ② 만기 기준 표본 필터** 두 전제 위에 서 있다. 특히 로지스틱을 되살리면 결측 관련 결론이 전부 원복된다(NaN을 못 받으므로 대체값·더미·표준화가 다시 필요해진다).

- **① 두 전제만으로 기존 쟁점 11건이 닫힌다**: 결측더미 개수, T2 더미 14개 완전공선성, `X_masked` 공식 오류, 표준화·로그변환, 캡핑, 대표변수 선정, T3 값컬럼 제거, 특수값 인코딩(전제 1) + 표본필터 방식, seasoning, 분할 방식(전제 2). 결측 처리 논쟁의 대부분이 **"NaN을 못 받는 모형"** 을 전제하고 있었기 때문이다.

- **② 36m/60m 분리 모형 — 채택하지 않는다** (#12 ⑤의 완화책 후보를 실측으로 기각):

  | 평가 구간 | (a) 통합 | (b) 분리 | Δ(b−a) | seed 편차 | 판정 |
  | --- | ---: | ---: | ---: | ---: | --- |
  | 전체 | 0.68080 | 0.68033 | −0.00047 | 0.00150 | 미세하게 나쁨(부호 5/5) |
  | 36개월 안에서 | 0.67197 | 0.67223 | +0.00025 | 0.00131 | 차이 없음 |
  | **60개월 안에서** | **0.62783** | **0.62219** | **−0.00564** | 0.00563 | **뚜렷하게 나쁨(5/5 seed)** |

  분리의 기대 이익이 가장 컸던 60m에서 오히려 손해가 났다. 이유는 표본 크기다 — 분리하면 60m 모형이 8만 건으로 학습하는데 통합하면 58만 건을 본다. 신용위험의 기본 패턴은 상품과 무관하게 공통이라 36m 데이터가 60m 예측에 전이된다. 또한 트리는 `term`을 피처로 주면 두 상품이 실제로 다르게 행동하는 지점에서 스스로 분기하므로, 사람이 미리 갈라 주면 **공통 패턴을 배울 기회를 뺏는** 셈이 된다.
  성능 밖의 비용도 크다 — Sharpe는 포트폴리오 단위 지표라 분리하면 threshold 탐색이 **(t36, t60) 2차원**이 되고(각각 최적화해 합치면 전체 Sharpe 최적 보장이 없다), 변수중요도가 두 세트가 된다(60m 모형에서는 T2 14개가 전량 결측이라 통째로 죽는다).
  → **통합 모형 + `term` 피처 투입.** 단 학습 후 예측값을 term으로 나눠 **성능표는 term별로 반드시 보고**한다(모형을 나누지 않고도 진단은 그대로 얻는다).
  → 주의: 이는 **PD 모형**을 나누지 않는다는 뜻이며, IRR·Sharpe 계산식에는 term별 현금흐름 기간이 반드시 들어간다(#4).

- **③ 결측 처리 — 전부 NaN 유지, 파생 더미 없음**: `preprocessing_validation_kgj.md` 4절이 "2016년 이후 금액·개수형은 0 대체가 옳다"고 권고했고 류성환·이지희 문서는 같은 구간에 중앙값 대체를 적어 대립했으나, **두 주장 모두 실효가 없다.**

  | T2 변수 | 성격 | 2016+ 결측률 |
  | --- | --- | ---: |
  | `il_util` | 비율형 | 14.12% |
  | `mths_since_rcnt_il` | 시점형 | 3.14% |
  | `all_util` | 비율형 | 0.02% |
  | 금액·개수형 11개 | 금액·개수형 | **0.01%** |

  "계좌가 없으면 잔액은 진짜 0"이라는 논리가 겨눈 **금액·개수형 변수에는 채울 결측이 남아 있지 않다**(25만 건 중 약 25건). 실제로 결측이 남는 두 변수는 분모가 0이라 **0이 틀린 값**이다.
  처리 스킴 4종(NaN 유지 / 비율·시점형까지 0 / NaN+`has_no_il_account` 더미 / 2016+ 전부 0)의 AUC 최대 차이는 **0.00009로 seed 편차(0.00134)의 1/15** 이고 부호도 seed마다 갈린다.
  `has_no_il_account` 더미가 불필요한 이유는 **`open_act_il`이 이미 피처에 있어** 트리가 `open_act_il < 1`로 직접 분기할 수 있기 때문이다 — 같은 정보를 두 번 넣는 것이다.
  → **T2 pre-2016(미수집)·T2 2016+(계좌 미보유)·T3(사건 없음) 전부 NaN 그대로 투입. 대체하지 않고 더미도 만들지 않는다.** #8의 GBM native 결측 처리 원칙과 동일한 결론이다.
  → 단 **2015년 이전 구간의 0 대체 금지**는 여전히 유효하다(그 구간은 "계좌가 없다"가 아니라 "안 물어봤다"이므로 0을 넣으면 옛 차주 전체를 무활동 차주로 왜곡한다).

- **④ 분할 방식 — 랜덤 6:2:2 유지**: 유명곤님이 제안한 시간순 분할은 채택하지 않는다. T2 수집 개시(2015-12)와 제안된 Train 종료(2015-11)가 한 달 차이로 배타적이라 **Train의 T2 관측률이 0.00%, Test가 100%** 가 된다(만기컷 적용 시에도 동일). GBM은 학습 때 전량 결측인 컬럼을 분기에 쓰지 않으므로 #12 ④에서 확정한 "T2 값은 남긴다"가 무효화된다. 만기컷을 걸면 문제가 하나 더 붙는다 — Train은 60m가 23.9% 섞이는데 **Valid·Test는 100% 36m**가 되어 학습과 검증이 서로 다른 상품을 보게 된다. 시간순 분할의 목적(낙관적 평가 방지)은 만기컷이 이미 달성하므로, 시간순은 필요할 때 **보조 진단**으로만 돌린다.

- **⑤ 실험 조건 및 인용 시 주의**: 위 수치는 모두 만기+버퍼6m 표본 723,563건 전량 · 랜덤 80/20(`stratify=y`) · XGBoost 동일 하이퍼파라미터(`n_estimators=300, max_depth=5, lr=0.08`) · seed 0~4 기준이다. 피처 32개는 `variable_dictionary_byGJ.xlsx`에서 **전부 `is_pre_approval=1`** 임을 대조 확인했다(사후 누수 변수 없음). 다만 `grade`·`sub_grade`·`int_rate` 등 **LC 조건변수는 제외한 Lean 스펙**이므로, **AUC 절대 수준(0.68)을 최종 모형 성능으로 인용하면 안 된다** — 처리 방식 간 상대 비교용이다(조건변수 포함 시 0.71대, 류성환님 문서 실측).

- **팀 협의 필요**: 없음. 본 항목은 두 전제가 확정되면 그대로 적용한다. 단 전제 1(XGBoost 단일화)이 뒤집히면 ③이 전부 원복된다.
