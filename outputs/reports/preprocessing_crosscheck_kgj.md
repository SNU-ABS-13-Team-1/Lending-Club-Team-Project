## 1. 두 가지 전제 — 확정하면 쟁점이 어떻게 정리되나

### 1.1 전제 내용

> **전제 1 — 모형은 XGBoost 하나로 간다.** 로지스틱 회귀[^logit]는 폐기한다.
>
> **전제 2 — `Current`뿐 아니라 "아직 만기가 오지 않은 대출"도 함께 삭제한다.** 발행연도가 아니라 **각 대출의 실제 만기일**을 기준으로 자른다.

이 절은 "두 전제가 옳은가"를 논증하는 자리가 아니다. **확정한다고 가정했을 때 무엇이 정리되는지**를 보여주는 것이 목적이다. 근거는 2절 이하 본문에 있고, 여기서는 결론만 연결한다.

다만 전제 2의 **"연도가 아니라 만기"** 라는 선택은 그 자체가 하나의 판단이므로 아래에 따로 설명한다.

### 1.2 왜 연도가 아니라 만기를 기준으로 삼는가

#### 우리가 재려는 것이 무엇인지부터

우리는 "이 대출이 **최종적으로** 부도났는가"를 예측하려 한다. 그러려면 학습 데이터의 정답이 **확정된 정답**이어야 한다.

그런데 데이터 스냅샷은 2020년 10월에 찍혔다. 만기가 아직 안 온 대출인데 결과가 이미 확정돼 있다면, 그건 둘 중 하나다.

```
 ① 조기 완납 (Fully Paid)  ← 예정보다 일찍 다 갚음
 ② 조기 부도 (Charged Off) ← 예정보다 일찍 못 갚게 됨
```

**문제는 이 둘의 비율이 정상 대출과 다르다는 것이다.** 만기까지 꼬박 갚아나가는 평범한 우량 대출은 스냅샷 시점에 아직 `Current`라서 표본에서 빠진다. 반면 부도는 대부분 초기에 터지므로 거의 다 잡힌다. 그래서 **미성숙 코호트[^cohort]는 부도율이 부풀려진다.**

실측이 정확히 그렇다.

| | 부도율 |
| --- | ---: |
| 만기가 **이미 도래한** 완결건 | **16.06%** |
| 만기가 **아직 안 온** 완결건 | **24.54%** |

**8.5%p 차이**다. 이 차이는 차주가 위험해서가 아니라 **아직 시간이 안 지나서** 생긴 것이다.

#### 예시로 보면

```
2018-06에 나간 36개월 대출  (만기 2021-06, 스냅샷 2020-10)

  이 대출이 지금 Charged Off 로 확정 → 2년 만에 부도난 것    → 표본에 들어옴
  이 대출이 지금 Fully Paid  로 확정 → 조기 상환한 것         → 표본에 들어옴
  이 대출이 지금 Current     → 정상적으로 갚는 중             → 표본에서 빠짐  ← 대다수
```

세 번째 유형이 통째로 빠지므로, 남은 표본은 실제보다 위험해 보인다.

#### 그럼 왜 연도 컷이 아니라 만기 컷인가

**이유 ① — 같은 해에 나갔어도 만기는 2년씩 차이 난다**

```
2015-06 발행
  ├ 36개월 상품 → 만기 2018-06 → 스냅샷보다 2년 이상 전에 끝남.  안전하게 쓸 수 있다
  └ 60개월 상품 → 만기 2020-06 → 스냅샷 4개월 전에 겨우 끝남.   상각 확정이 덜 됐을 수 있다
```

**발행연도는 성숙도를 재는 대리변수일 뿐이고, 만기는 `issue_d + term`으로 직접 계산할 수 있다.** 직접 잴 수 있는 것을 두고 대리변수를 쓸 이유가 없다.

**이유 ② — 연도 컷은 멀쩡한 데이터를 버린다**

팀 검토안(`36m: 발행연도 < 2017`, `60m: 발행연도 < 2015`)은 **이미 만기가 도래한 187,821건**을 발행연도가 늦다는 이유만으로 버린다.

```
36개월 · 2017년 발행 : 128,435건   ← 만기 2020년 초 = 스냅샷 전에 이미 끝남
60개월 · 2015년 발행 :  59,386건   ← 만기 2020년 = 마찬가지
                       ─────────
                       187,821건 (부도율 21.17%) 을 이유 없이 폐기
```

만기 기준으로 바꾸면 **같은 청정도를 유지하면서 79,428건을 되찾는다.**

**이유 ③ — 청정도를 숫자로 직접 확인할 수 있다**

각 규칙이 남긴 발행구간 안에 **아직 상환 중인 대출(`Current`)이 얼마나 있는가**를 보면 된다. 이 비율이 0에 가까울수록 "그 시기 대출은 이미 다 끝났다" = 미성숙 오염이 없다는 뜻이다.

| 규칙 | 완결표본 | **구간 내 `Current`** | 판정 |
| --- | ---: | ---: | --- |
| 현행 (`Current`만 제외) | 1,117,571 | **35.2%** | 오염이 심하다 |
| 연도 컷 (팀 검토안) | 644,135 | 0.00% | 깨끗하지만 **과보수적** |
| 만기 컷 (버퍼 없음) | 831,956 | 4.14% | 상각 지연분이 섞인다 |
| **만기 컷 + 버퍼 6개월** | **723,563** | **0.06%** | **같은 청정도로 +79,428건** |

**버퍼 6개월을 두는 이유**: 연체가 최종 상각(charge-off)으로 확정되기까지 통상 4~5개월이 걸린다. 만기 직후 데이터는 "부도인지 아닌지" 아직 진행 중일 수 있으므로 여유를 준다. 실제로 버퍼 없이 자르면 구간 내 `Current`가 4.14%로 남는데, 6개월을 주면 **0.06%**까지 떨어진다.

> **한 줄 요약**: 연도 컷은 "2017년 이후는 위험할 것 같으니 다 버리자"는 어림짐작이고,
> 만기 컷은 "이 대출은 2020년 4월에 끝났으니 결과가 확정됐다"는 **개별 판정**이다.
> 어림짐작은 멀쩡한 것도 버리고 위험한 것도 남긴다.

#### 전제 2가 치르는 대가 — 함께 기록해 둘 것

만기를 요구하면 공짜가 아니다. 세 가지가 따라온다.

- **표본이 723,563건으로 준다** (현행의 65%), 부도율은 19.49% → **16.21%** 로 내려간다.
- **AUC[^auc] 수준 자체가 내려간다** (0.6996 → 0.6763). 다만 우리 판단 기준은 Sharpe Ratio이므로 AUC 하락 자체가 필터를 기각할 근거는 아니다.
- **term-vintage 교락이 생긴다.** 만기를 요구하면 뒤쪽 시기에는 36개월만 남는다. 60개월 비중이 현행 25.1% → 13.9%로 줄고, 발행연도와 상품이 얽힌다. 완화책 후보로 **36개월/60개월 분리 모형**이 거론됐으나, 실측 결과 통합이 낫다는 결론이 나왔다(8절).
- **발행기간이 2007-06 ~ 2017-04로 끝난다.** 2017~2020 구간(금리 인상기·COVID)이 표본에서 사라지므로 **거시지표 사용 여부**(`decision_log.md` #11)를 다시 판단해야 한다.

### 1.3 전제 1(XGBoost 단일화)이 닫는 쟁점 — 8건

로지스틱을 버리면 **로지스틱 때문에 존재하던 쟁점이 통째로 사라진다.** 결측 처리 논쟁의 대부분이 "NaN을 못 받는 모형"을 전제하고 있었기 때문이다.

| # | 쟁점 | 어떻게 닫히나 | 근거 |
| --- | --- | --- | --- |
| 1 | **결측더미**[^dummy] **0개 vs 1개** | **0개로 확정** | 더미가 기여한 건 로지스틱뿐(0.68074 → 0.67876). XGBoost[^xgb]는 Δ +0.00003이고 out-of-time[^oot]에선 없는 쪽이 나았다 (6절 쟁점 A) |
| 2 | T2 더미 14개 = 완전공선성 | **문제 자체가 소멸** | 특이행렬[^singular]은 선형모델의 병이고 트리는 무해하다 (5절 ①) |
| 3 | **`X_masked = X × D_X` 부호 오류** | **논쟁 소멸** | 이 기법은 "절편 이동 + 기울기 분리"라는 선형모델 장치다. NaN을 그대로 넣으면 필요 없다 (9절) |
| 4 | 표준화·로그변환·구간화 | **전부 불필요로 확정** | 트리는 값의 **순서**만 쓴다. 류성환님의 2트랙 분기표가 통째로 필요 없어진다 |
| 5 | **캡핑**[^capping] (류성환 vs 유명곤) | **사실상 무쟁점** | 캡핑은 단조변환[^mono]이라 트리 결과가 안 변한다. 오히려 `dti` 999를 100으로 자르면 **진짜 100인 행과 뭉개져 정보가 준다** → 유명곤님의 "원본 유지"가 자동 채택 |
| 6 | 대표변수 선정 (`sub_grade` vs `int_rate`) | **예측 목적에선 소멸** | 트리는 셋 다 넣어도 예측에 무해. 변수중요도 **해석** 목적으로만 남는다 |
| 7 | T3 무신호 3개의 값 컬럼 제거 | **소멸 — 그냥 다 남긴다** | 내 주장의 핵심 근거가 "NaN 55만 건을 뭘로 채우나"였는데 채울 필요가 없어졌다 |
| 8 | 999·−1 특수값 인코딩 (이지희 대안) | 불필요 | 같은 이유 |

### 1.4 전제 2(만기 기준 필터)가 닫는 쟁점 — 3건

| # | 쟁점 | 어떻게 닫히나 |
| --- | --- | --- |
| 9 | `decision_log.md` #12 ① **연도 컷 vs 만기 컷** | **만기 + 버퍼 6개월로 확정** (1.2 근거) |
| 10 | **seasoning 편향**[^seasoning] (#11 원인 ②) | **해소.** 8.5%p 왜곡이 표본 단계에서 제거된다 |
| 11 | **분할 방식**[^split] **— 랜덤 vs 시간순** | **시간순 분할이 배제된다** → 현행 랜덤 6:2:2 유지 (7절에 실측) |

11번은 예상 밖의 부수효과다. **만기 컷과 시간순 분할은 궁합이 나쁘다** — 만기를 요구하는 순간 뒤쪽 시기에 36개월만 남으므로, 시간순으로 자르면 학습과 검증이 서로 다른 상품을 보게 된다. 상세는 7절.

### 1.5 두 전제로도 안 풀리는 것 — 0 + 5건

**두 전제가 반쯤 열어 둔 항목 2건은 실측으로 닫았다**

| 쟁점 | 결과 |
| --- | --- |
| **36개월/60개월 분리 모형** | 전제 2가 term 구성을 바꾸면서(60m 비중 25.1% → 13.9%) 새로 떠오른 항목이다. 실측 결과 **분리는 이득이 없고 60개월에서 5/5 seed 모두 나빠졌다** → **통합으로 확정** (8절) |
| **2016+ 잔여 결측 → 0 vs NaN** | 전제 1이 "중앙값 대체"를 없앤 뒤 남은 항목이다. 실측 결과 **0을 채울 대상 자체가 없고**(금액·개수형 2016+ 결측률 0.01%) **네 스킴의 AUC가 구분 불가**다 → **전부 NaN 유지** (6절 쟁점 B) |

**반드시 정해야 하는 항목 — 없음**

## 2. 지금 어떤 문서들이 있나

우리 팀은 "류성환님이 만든 변수분류 시트가 타당한가"를 각자 검증했다. 그 결과물이 네 개다.

| 문서 | 분량 | 어떤 각도로 봤나 |
| --- | ---: | --- |
| **류성환 (rsh)** | 124줄 | 로지스틱과 XGBoost는 필요한 전처리가 다르니 **2트랙으로 나누자** |
| **유명곤 (ymg)** | 254줄 | XGBoost 하나로 가되, **데이터를 시간순으로 쪼개자** |
| **이지희 (jh)** | 303줄 | 결측치를 **원인별로 4단계(T0~T3)** 로 분류하고 각각 처방 |
| **강권재 (kgj)** | 663줄 | 시트의 **계산 오류 4건**을 잡고, 표본 정의가 바뀌어도 결론이 유지되는지 확인 |

> 참고: 이지희님 문서는 "결측치 분석"이라는 다른 제목이라 놓치기 쉬운데, 실제 내용은 같은 주제다.
> 특히 T2 처리에서 다른 문서들과 부딪히는 부분이 있으니 반드시 함께 봐야 한다.

## 3. 먼저 — T2 변수가 뭐고 왜 문제인가

### 상황을 비유로 먼저

어떤 회사가 2007년부터 고객 설문을 받아왔다고 하자. 그런데 **2015년 12월에 설문지에 새 문항 14개를 추가**했다.

그러면 데이터는 이렇게 생긴다.

```
2014년 고객 → 새 문항 14개가 전부 빈칸
2016년 고객 → 새 문항 14개가 전부 채워짐
```

이때 "빈칸인 사람"과 "채워진 사람"의 성향이 다르다면, 그건 사람이 달라서일까 **설문지가 달라서**일까?

Lending Club 데이터에서 정확히 이 일이 벌어졌다. `il_util`(할부계좌 사용률), `all_util`(전체 계좌 사용률), `open_acc_6m`(최근 6개월 개설 계좌 수) 등 **14개 변수가 2015년 12월부터 수집되기 시작**했다. 그래서 그 이전 대출은 이 14개가 통째로 비어 있다.

```
연도별 T2 결측률
  2007 ~ 2014 : 100%   ← 아예 안 물어봤음
  2015        :  95%   ← 12월부터 수집 시작
  2016 ~ 2020 :   0%   ← 전부 수집됨
```

### 왜 이게 함정인가

시트의 원래 아이디어는 **"결측 자체가 정보"** 라는 것이었다. 예를 들어 "마지막 연체 후 몇 개월?"이 비어 있으면 → 연체한 적이 없다는 뜻 → 우량 고객. 이건 맞는 논리다.

그래서 T2에도 같은 논리를 적용하려 했고, 실제로 숫자가 그럴듯하게 나왔다.

| | 부도율 |
| --- | ---: |
| T2가 비어 있는 사람 | 18.03% |
| T2가 채워진 사람 | 20.71% |

**"결측인 사람이 2.7%p 더 우량하다"** 로 보인다. 그런데 위의 연도별 표를 다시 보자.

```
T2가 비어 있는 사람  =  2007~2015년에 대출받은 사람
T2가 채워진 사람     =  2016~2020년에 대출받은 사람
```

**비교하고 있는 게 "결측 여부"가 아니라 "대출받은 시기"다.** 두 시기는 원래 부도율이 다르다.

### 결정적 증거 — 연도를 고정하면 신호가 사라진다

두 집단이 **같은 해에** 공존하는 유일한 연도가 2015년이다. 여기서만 비교하면:

| 2015년 대출만 | 건수 | 부도율 |
| --- | ---: | ---: |
| T2 관측 | 3,275 | 19.54% |
| T2 결측 | 61,441 | 19.71% |

차이 **0.17%p** — 사실상 없다. 아까 보이던 2.7%p는 전부 시기 차이였던 것이다. 이걸 통계에서는 **교란**[^confound]이라고 한다.

> 류성환님은 같은 것을 다른 각도로 확인했다. 2015년 12월 **이후**로만 잘라서 비교하니
> 결측군 21.76% vs 관측군 20.71%로 **부호가 아예 뒤집혔다**(+1.05%p).
> 방법은 다르지만 결론은 동일하다 — 원래 보이던 격차는 진짜가 아니었다.

**이건 우리가 이미 한 번 겪은 문제다.** `decision_log.md` #11에서 거시지표 4종이 전부 이론과 반대 부호로 나왔던 원인이 `corr(실업률, 발행연도) = −0.911`이었다. T2 결측더미는 정확히 같은 병인데, 다만 **부호가 그럴듯해서 눈에 안 띄었을 뿐**이다.

## 5. 이미 합의된 것 — 더 논의하지 않아도 되는 항목

세 사람 이상이 **각자 독립적으로** 같은 결론에 도달한 것들이다. 이 정도면 확정해도 된다.

### ① T2 결측더미 14개를 개별로 만들지 않는다

시트의 원안대로 하면 T2 14개 각각에 더미를 붙여 컬럼이 14개 늘어난다. 그런데 **이 14개 더미는 서로 완전히 같은 컬럼**이다. 같이 비고 같이 채워지니까 당연하다.

같은 컬럼을 14장 복사해서 로지스틱에 넣으면 **계산 자체가 안 된다**. 이건 "복잡해진다" 수준이 아니라 수치적 결함이다. 류성환님·이지희님·나 모두 같은 지적을 했다.

> **전제 1을 확정하면 이 항목은 아예 논점이 아니게 된다** — 트리 모형에는 완전공선성 문제가 없기 때문이다. 다만 "더미를 만들지 않는다"는 결론은 그대로 유효하다.

### ② T2 변수의 값은 살린다

더미는 가짜지만 값은 진짜다. 실제로 T2 14개 변수를 통째로 빼면 예측력이 확실히 떨어진다.

| 표본 | T2를 뺐을 때 AUC 변화 | 잡음 대비[^noise] |
| --- | ---: | ---: |
| 현행 표본 | −0.0075 | 2.1배 |
| 만기컷[^maturity] 적용 후 | −0.0048 | 2.5배 |
| 만기컷 + 36개월만 | **−0.0085** | **5.7배** |

**요약하면 "값에는 정보가 있고, 더미에는 없다."** 전제 2를 적용해 표본이 줄어도 이 결론은 유지된다 — 오히려 36개월 분리 모형에서 기여가 가장 크다.

### ③ `emp_length`(근속연수) 최빈값 대체 금지

근속연수를 **안 적은 사람**의 부도율이 26.3%, 적은 사람이 19.0%다. **+7.2%p로 전 변수 중 최대 격차**다. 근속연수는 차주가 직접 기재하는 항목이라, 안 적었다는 사실 자체가 불안정한 고용 상태의 신호로 보인다.

시트의 원안은 "`Missing` 처리 **또는 최빈값**"인데, 최빈값이 `10+ years`(근속 10년 이상)다. 이걸 채우면 **가장 위험한 집단이 가장 안전한 집단으로 둔갑**한다.

류성환님도 독립적으로 +7.24%p를 측정했고, "최고위험군을 최저위험군으로 둔갑"이라는 똑같은 표현을 썼다. → **`Missing` 별도 범주로 확정.**

### ④ 기타 합의 사항

- T3 변수(연체·파산 이력 경과월)는 "결측 = 사건 없음 = 우량"이 **맞다**. 나와 류성환님의 측정치가 소수점까지 일치한다.
- XGBoost에는 **표준화·로그변환이 불필요**하다 (세 사람 동의). 트리는 값의 순서만 보기 때문에 단조변환에 결과가 안 변한다.
- `grade`/`sub_grade`/`int_rate`는 상관 0.95~0.97로 사실상 같은 정보다. **해석**할 때는 1개만 봐야 한다.

## 6. 아직 갈리는 것 — 둘 다 닫혔다

### 쟁점 A. 결측더미를 1개 만들 것인가, 0개 만들 것인가

> **전제 1을 확정하면 → 0개로 해소.** 아래는 그 근거다. (쟁점 B도 실측으로 닫혔다 — 뒤쪽 참고)

| 입장 | 근거 |
| --- | --- |
| 이지희: **1개 필수** | 모델이 "이 행은 옛날 대출"임을 인지해야 한다 |
| 류성환: **1개, 다만 생략 가능** | 연도더미와 98.85% 중복이라 어차피 잉여 |
| 강권재: **0개 권고** | 실전에서 켜지지도 않는다 (아래) |

내가 0개를 권고하는 이유는 **out-of-time 검증** 때문이다. 학습을 2016년 이전, 검증을 2017~2019년으로 잡고 더미가 켜지는 비율을 봤다.

| | 학습 구간 | 검증 구간 |
| --- | ---: | ---: |
| 더미 = 1인 비율 | 66.6% | **0.0%** |

**학습 데이터의 2/3에서 1이던 변수가, 실전에서는 항상 0이다.** 모델이 이 변수에 의존해 배운 것은 실전에서 전부 무용지물이다. 실제로 더미를 뺀 쪽이 out-of-time AUC가 더 높았다 (0.69305 vs 0.69257).

이 논쟁이 갈렸던 이유는 **모델별로 답이 달랐기 때문**이다. 로지스틱은 NaN을 받지 못하므로 더미가 실제로 기여한다(0.68074 vs 0.67876). 그래서 류성환님의 2트랙 구조가 의미가 있었다. **전제 1로 로지스틱을 버리면 이 분기 자체가 사라진다.**

### 쟁점 B. 2016년 이후에 남는 결측을 어떻게 채울 것인가 ← **실측으로 해소**

> **전제 1이 "중앙값 대체" 주장을 없애고, 남은 "0 vs NaN"은 실측으로 닫혔다 → 전부 NaN 유지.**

류성환님과 이지희님은 둘 다 **"2015년 이후 잔여 결측은 중앙값 대체"** 라고 썼다.

**왜 그대로 두면 안 되나.** 2016년 이후에도 결측이 남는 변수가 2개 있는데, 그 결측의 원인을 파보면 이렇다.

| 2016년 이후 잔여 결측 | 결측률 | 결측건 중 `open_act_il = 0`인 비율 |
| --- | ---: | ---: |
| `il_util` (할부계좌 사용률) | 14.07% | **75.0%** |
| `mths_since_rcnt_il` (최근 할부계좌 개설 후 경과월) | 2.88% | **99.8%** |

`open_act_il = 0`은 **활동 중인 할부계좌가 0개**라는 뜻이다. 즉 이 사람들은 데이터가 누락된 게 아니라, **할부계좌가 애초에 없어서 사용률이 수학적으로 정의되지 않는** 것이다.

```
il_util (할부계좌 사용률) = 할부계좌 총잔액 ÷ 할부계좌 총한도
                          = 0 ÷ 0
                          = 정의 불가  ← 누락이 아님
```

여기에 중앙값(사용률 약 70%)을 넣으면 **"할부계좌가 없는 사람"을 "할부금을 평균적으로 쓰고 있는 사람"으로 만드는** 셈이다. 게다가 이 결측은 진짜 신호를 담고 있다 — `mths_since_rcnt_il`이 결측인 사람의 부도율은 20.60% → **24.98%**로 **+4.38%p 더 위험**하다.

**전제 2를 적용해도 이 문제는 사라지지 않는다.** 만기 컷 후에도 2016년 이후 발행이 **250,312건(표본의 34.6%)** 남기 때문이다.

| 만기컷 표본 ∩ 2016년 이후 발행 | 결측률 | `open_act_il = 0` 비율 | 부도율 차이 |
| --- | ---: | ---: | ---: |
| `il_util` | 14.12% (35,344건) | **77.8%** | −1.11%p |
| `mths_since_rcnt_il` | 3.14% (7,854건) | **99.7%** | **+1.60%p** |

신호는 약해지지만(+4.38%p → +1.60%p) 구조는 그대로다.

**남는 결정은 "0으로 볼까 NaN으로 둘까" 하나로 좁혀진다** — 고 정리했었는데, 실측해보니 **그 결정조차 필요 없었다.**

#### 실측 ① — 0을 채울 대상 자체가 없다

"계좌가 없으면 잔액은 진짜 0"이라는 논리는 **금액·개수형 변수**를 겨냥한 것이었다. 그런데 그 변수들에는 2016년 이후 채울 결측이 남아 있지 않다.

| T2 변수 | 성격 | **2016+ 결측률** |
| --- | --- | ---: |
| `il_util` | 비율형 | **14.12%** |
| `mths_since_rcnt_il` | 시점형 | **3.14%** |
| `all_util` | 비율형 | 0.02% |
| `total_bal_il`·`open_il_12m`·`open_act_il`·`max_bal_bc`·`inq_fi` 외 **금액·개수형 11개** | 금액·개수형 | **0.01%** |

**0.01%면 25만 건 중 약 25건이다.** 결측이 실제로 남는 두 변수는 애초에 0이 틀린 변수다 — 분모가 0이라 정의 불가지, 값이 0인 게 아니다.

#### 실측 ② — 네 스킴이 전부 같다

만기컷 표본 723,563건 · XGBoost · seed 0~4:

| 스킴 | AUC | NaN 유지 대비 | 나쁜 seed |
| --- | ---: | ---: | ---: |
| **N — NaN 유지** | **0.68080** | — | (seed 편차 **0.00134**) |
| Z — 비율·시점형까지 0으로 | 0.68074 | −0.00006 | 3/5 |
| D — NaN + `has_no_il_account` 더미 | 0.68089 | +0.00009 | 2/5 |
| Za — 2016+ 모든 T2 결측을 0으로 | 0.68089 | +0.00009 | 2/5 |

최대 차이 0.00009는 seed 편차의 **1/15**이고 부호도 seed마다 갈린다(2/5, 3/5). 구분이 불가능하다.

#### 결론 — 전부 NaN으로 두고 아무것도 만들지 않는다

- **성능이 같으면 단순한 쪽**을 택한다. 의미상으로도 `0 ÷ 0`에 0을 넣는 것은 틀렸다.
- **`has_no_il_account` 더미도 불필요하다.** 이 문서가 "이견이 적을 것"이라며 권고했던 항목인데 기여가 잡음의 1/15이다. 이유는 명확하다 — **`open_act_il`이 이미 피처로 들어가 있어서** 트리가 `open_act_il < 1`로 직접 분기할 수 있다. 더미는 같은 정보를 두 번 넣는 것이다.
- 이는 **쟁점 A(결측더미 0개)와 정확히 같은 결론**이다. XGBoost를 쓰면 결측 관련 파생 컬럼은 전부 불필요하다는 원칙이 여기서도 성립한다.

```
전제 1(XGBoost) 하에서 결측 처리 규칙 — 하나로 통일된다

  T2 pre-2016 → NaN 그대로   (미수집)
  T2 2016+    → NaN 그대로   (계좌 미보유 — open_act_il이 이미 그 정보를 담고 있다)
  T3          → NaN 그대로   (사건 없음)
  파생 더미     → 만들지 않음
```

> **주의 ①**: 이 결론은 **XGBoost를 쓴다는 전제**에 의존한다. NaN을 받지 못하는 선형모형을 쓴다면 대체값과 더미가 다시 필요해진다.
>
> **주의 ②**: "0 대체 금지"라는 시트의 원칙은 **2015년 이전 구간에 대해서는 여전히 옳다.** 그 구간은 "계좌가 없다"가 아니라 "안 물어봤다"이므로, 0을 넣으면 옛날 차주 전체를 무활동 차주로 왜곡한다. 위 실측에서도 0 대체는 **2016년 이후 발행분에만** 적용했다.

**재현**: `src/analysis/missing_scheme_comparison.py` · 결과표 `outputs/missing_scheme_comparison.csv`

## 7. 분할 방식 — 시간순 분할은 T2를 죽인다

### 유명곤님의 제안은 무엇인가

유명곤님 문서의 가장 큰 기여는 **분할 방식**에 대한 것이다. 지금 우리 규칙은 **랜덤 분할**(전체를 무작위로 6:2:2)인데, 이러면 2013년 대출과 2017년 대출이 학습·검증에 골고루 섞인다. 그러면 "미래를 예측하는 능력"이 아니라 "같은 시기를 외우는 능력"을 측정하게 될 수 있다.

그래서 **시간순 분할**을 제안했다.

```
Train      : ~2015-11        (과거로 배우고)
Validation : 2015-12~2016-09 (조금 뒤 시점으로 고르고)
Test       : 2016-10~2017-09 (더 뒤 시점으로 검증)
```

**방향 자체는 타당하다.** 실제 대출 심사가 그렇게 작동하기 때문이다.

### 문제 ① — 현행 표본에서도 T2가 죽는다

원본 175만 행으로 직접 확인했다. (유명곤님 문서의 건수·부도율이 정확히 재현됐다 — 분할안 자체는 검증됨)

| Partition | 발행기간 | 건수 | 부도율 | **T2 관측률** |
| --- | --- | ---: | ---: | ---: |
| Train | ~2015-11 | 483,626 | 17.54% | **0.00%** |
| Validation | 2015-12~2016-09 | 165,067 | 16.04% | 94.36% |
| Test | 2016-10~2017-09 | 165,928 | 16.29% | **100.00%** |

**T2 14개 변수가 학습 데이터에서 100% 비어 있고, 테스트에서 100% 채워져 있다.**

당연한 결과다. T2 수집이 2015년 12월에 시작됐는데, Train이 2015년 11월에 끝나기 때문이다. 두 날짜가 딱 한 달 차이로 어긋난다.

```
T2 수집 개시  : 2015-12
Train 종료    : 2015-11    ← 한 달 차이로 완전히 배타적
```

**결과**: 모델은 T2를 **한 번도 본 적 없이** 학습을 끝내고, 실전에서는 T2가 **항상 들어온다**. XGBoost는 학습 때 전량 결측인 컬럼을 분기에 아예 쓰지 않으므로, T2는 **사실상 삭제된 것과 같아진다.** 즉 5절 ②에서 세 사람이 합의한 "T2 값은 살린다"가 분할 규칙 하나로 무효화된다.

### 문제 ② — 전제 2를 적용하면 더 나빠진다

만기 컷을 건 표본(723,563건)에 같은 방식으로 시간순 60/20/20을 적용하면:

| Partition | 발행기간 | 건수 | 부도율 | **T2 관측률** | **60개월 비중** |
| --- | --- | ---: | ---: | ---: | ---: |
| Train | 2007-06~2015-09 | 419,715 | 16.77% | **0.00%** | **23.9%** |
| Validation | 2015-10~2016-06 | 156,263 | 15.54% | 71.44% | **0.0%** |
| Test | 2016-07~2017-04 | 147,585 | 15.34% | **100.00%** | **0.0%** |

문제가 **두 개로 늘어난다.**

1. **T2는 여전히 죽는다** — Train 0%, Test 100%. 만기 컷을 걸어도 그대로다.
2. **term 구성이 완전히 갈린다** — Train은 60개월이 24% 섞여 있는데 **Validation·Test는 100% 36개월**이다. 60개월 대출은 만기가 오려면 2015년 이전에 나갔어야 하므로 구조적으로 뒤쪽 구간에 존재할 수 없다.

즉 **만기 컷과 시간순 분할은 궁합이 나쁘다.** 만기를 요구하는 순간 "뒤쪽 시기 = 36개월만"이 되어버려, 시간순으로 자르면 학습과 검증이 서로 다른 상품을 보게 된다.

랜덤 분할이면 어디를 잘라도 **T2 관측률 35.8%, 60개월 비중 13.9%로 균일하다.**

### 결론 — 전제 2를 확정하면 랜덤 분할로 정리된다

시간순 분할을 하려던 목적은 **낙관적 평가를 막는 것**이었다. 그런데 **만기 컷이 이미 그 일을 한다** — 미성숙 코호트를 표본 단계에서 제거하므로 검증셋에도 편향이 섞이지 않는다.

목적을 이미 달성한 상태에서 시간순 분할을 고집하면, 얻는 것 없이 T2 상실과 term 불일치라는 대가만 치른다.

> **→ 현행 랜덤 6:2:2를 유지한다.** 시간순 분할은 필요할 때 **보조 진단**으로만 돌린다.
> 참고로 `decision_log.md` #12 정정 기록에 적힌 대로, 팀 공식 규칙은 원래부터 랜덤 6:2:2다.

### 이건 누구의 실수인가 — 아무의 실수도 아니다

유명곤님 문서 §1.3에는 "T2 결측이 발행연도를 대리하는지 **시간 외 검증이 필요하다**"고 적혀 있다. 문제를 인지는 하고 있었다. 다만 자신이 제안한 분할이 그 문제를 **극단으로 몰고 간다**는 데까지는 가지 않았다.

거꾸로 T2를 분석한 사람들(류성환·이지희·나)은 **랜덤 분할을 전제**하고 있었다.

**두 결론이 각각은 옳은데, 합치면 충돌한다.** 그래서 아무도 못 봤다.

## 8. 36개월/60개월을 나눌 것인가 — 실측: 나누지 않는 편이 낫다

`decision_log.md` #12 ⑤가 term-vintage 교락의 완화책으로 올려 둔 후보다. 전제 2를 확정하면
반드시 답해야 하는 항목이라 실측했다.

**재현**: `src/analysis/term_split_comparison.py` · 결과표 `outputs/term_split_comparison.csv`

### 8.1 왜 이게 쟁점이 되나 — 만기 컷이 term 구성을 바꾼다

만기 컷은 상품별로 **다른 발행 상한**을 요구한다.

```
36개월 : issue_d ≤ 2017-04    (2017-04 + 36개월 = 2020-04)
60개월 : issue_d ≤ 2015-04    (2015-04 + 60개월 = 2020-04)
                                ↑ 2년 더 짧다
```

60개월은 만기가 2년 늦게 오니 같은 마감일을 맞추려면 2년 더 일찍 나갔어야 한다. 그런데
Lending Club은 그 2년 사이에 대출을 크게 늘렸다. **잘려나가는 구간이 곧 물량이 가장 많던
구간**이라 60개월이 3분의 2 날아간다.

| | 만기컷 전 | 만기컷 후 | 잔존율 | 최종 비중 | 부도율 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 36개월 | 837,476 | 623,125 | 74.4% | **86.1%** | 14.61% |
| 60개월 | 280,095 | 100,438 | **35.9%** | **13.9%** | **26.18%** |

두 상품은 부도율이 **11.6%p** 차이 난다. 60개월 비중이 25.1% → 13.9%로 줄면 차주가
안전해진 게 아닌데도 전체 부도율이 내려간다(19.49% → 16.21%). 이 하락분에는 **진짜 개선
(seasoning 제거)** 과 **구성 변화(위험한 60개월이 빠짐)** 가 섞여 있다.

그래서 "상품별로 모형을 따로 만들어야 하는 것 아닌가"라는 질문이 나온다.

### 8.2 실측 — 같은 표본·같은 하이퍼파라미터·같은 test set

```
(a) 통합 : 전체로 모형 1개. term을 피처로 투입
(b) 분리 : 36m/60m 각각 모형 1개씩. term은 그룹 내 상수라 제외
```

(b)의 전체 AUC는 두 모형의 예측확률을 각 행의 term에 맞춰 이어 붙여 계산했다.

| 평가 구간 | (a) 통합 | (b) 분리 | 차이 (b−a) | seed 잡음 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전체 | 0.68080 | 0.68033 | −0.00047 | 0.00150 | 미세하게 나쁨 |
| 36개월 안에서 | 0.67197 | 0.67223 | +0.00025 | 0.00131 | 차이 없음 |
| **60개월 안에서** | **0.62783** | **0.62219** | **−0.00564** | 0.00563 | **뚜렷하게 나쁨** |

60개월은 차이와 잡음이 비슷한 크기라 **seed별 부호**를 따로 확인했다.

| seed | 0 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 분리 − 통합 (60개월) | −0.00477 | −0.00765 | −0.00414 | −0.00517 | −0.00648 |

**5/5 전부 음수다.** 우연으로 보기 어렵다.

즉 **분리의 기대 이익이 가장 컸던 곳에서 오히려 손해가 났다.**

### 8.3 왜 이런 결과가 나오나

**이유 ① — 표본 크기**

```
분리 60m 모형 : 60개월 데이터 8만 건만 본다
통합 모형     : 36개월 50만 + 60개월 8만 = 58만 건을 본다
```

신용위험의 기본 패턴(FICO가 낮으면 위험, dti가 높으면 위험)은 **상품 종류와 무관하게
공통**이다. 그래서 36개월 데이터로 배운 것이 60개월 예측에도 그대로 도움이 된다.
데이터를 7배 더 본 모형이 이기는 것이 자연스럽다.

**이유 ② — 트리는 필요하면 스스로 나눈다**

`term`을 피처로 넣어 두면, 두 상품이 정말 다르게 행동하는 지점에서 XGBoost가 알아서
`term < 48`로 분기한다. 사람이 미리 갈라 줄 필요가 없다.

오히려 사람이 갈라 버리면 **그 분기를 강제하는 대신 공통 패턴을 배울 기회를 뺏는** 셈이다.
"나누면 각 상품에 특화된다"는 직관이 성립하려면 각 그룹의 표본이 충분해야 하는데,
60개월 8만 건은 그러기에 부족했다.

### 8.4 성능 밖의 비용 — 실은 이쪽이 더 크다

성능이 같더라도 분리는 두 가지 비용을 더 치른다.

**비용 ① — threshold 탐색이 2차원이 된다**

우리 판단 기준은 AUC가 아니라 **Sharpe Ratio**다. 여기서 문제가 커진다.

```
(a) 통합 : PD 하나 → threshold 하나          → 1차원 탐색
(b) 분리 : PD 두 개 → threshold 두 개(t36, t60) → 2차원 탐색
```

단순히 계산량 문제가 아니다.

- **Sharpe는 포트폴리오 단위 지표다.** 36개월 포트폴리오와 60개월 포트폴리오를 각각
  최적화한 뒤 합치면 전체 Sharpe가 최적이라는 보장이 없다 — 두 그룹 수익률의 공분산이
  무시되기 때문이다.
- 제대로 하려면 (t36, t60) 격자를 **동시에** 탐색해야 한다. Validation에서 맞추는
  파라미터가 1개에서 2개로 늘어나므로 **과적합 위험도 커진다.**

**비용 ② — 변수중요도가 두 세트가 된다**

발표에서 이런 질문에 답해야 한다.

- "36개월에서는 `dti`가 3위인데 60개월에서는 7위인 이유가 뭔가요?"
- "60개월 모형에서 T2 변수 14개가 전부 안 쓰인 이유가 뭔가요?"

마지막이 특히 까다롭다. **60개월은 만기 조건상 2015-04까지만 남는데 T2 수집은 2015-12부터**라
전량 결측이다(3절·8.1). 같은 변수 목록을 넣었는데 한쪽 모형에서만 통째로 죽어 있는 것을
설명해야 한다. 통합이면 중요도가 한 세트고 `term`이 그냥 변수 하나로 순위에 들어간다.

### 8.5 결론 — 통합 모형 + term별 성능표

분리의 진짜 가치는 **모형을 나누는 것**이 아니라 **결과를 나눠 보는 것**이었다.
그리고 후자는 거의 공짜다.

```python
# 통합 모형 하나로 학습한 뒤, 예측값을 term으로 나눠 집계만 하면 된다
for t in (36, 60):
    sub = valid[valid.term_m == t]
    report(auc=..., 부도율=..., 승인율=..., Sharpe=...)
```

이러면 "36개월과 60개월 성능이 다르다"는 진단을 보고하면서도 모형은 하나로 유지된다.
유명곤님 문서 §3.2도 *"별도 모델로 학습하거나 **최소한 term별 성능표를 반드시 보고**한다"* 로
이 여지를 열어 뒀다.

> **한 가지 구분** — 이것은 **PD 모형**을 나누지 않는다는 뜻이지, 수익률 계산에서 term을
> 무시한다는 뜻이 아니다. 60개월 대출은 5년간 현금흐름이 나오므로 IRR·Sharpe 계산식에는
> 만기가 반드시 들어간다(`decision_log.md` #4).
>
> ```
> PD 모형         : 통합 (term을 피처로 투입)      ← 나눌 필요 없음
> IRR·Sharpe 계산 : term별로 현금흐름 기간이 다름  ← 반드시 반영
> ```

## 9. T2 밖의 쟁점들

### 합의된 것

- Target Encoding[^te]은 **train 내부에서만** 학습한다 (그러지 않으면 정답을 미리 보는 누수가 된다).
- 최종 판단 기준은 accuracy가 아니라 **Sharpe Ratio**다 (프로젝트 원칙과 일치).
- 원본 CSV 175만 행 중 1행은 대출이 아니라 설명문 메타행이므로 제거한다.

### 갈리는 것 — 전제 1이 세 건을 닫는다

| 쟁점 | 대립 | 전제 1 적용 시 |
| --- | --- | --- |
| **이상치 캡핑** | 류성환: `dti` 100, `revol_util` 150으로 **자르자** ↔ 유명곤: **자르지 말고** 원본 유지 후 민감도 비교 | **유명곤 안으로 해소.** 캡핑은 단조변환이라 트리 결과가 안 변하고, 오히려 `dti` 999를 100으로 자르면 진짜 100인 행과 뭉개진다 |
| **`X_masked` 공식 오류** | 나: `X × D_X`는 **부호가 반대**라 작동 안 함 ↔ 이지희: 이 공식을 "최적의 접근법"으로 **승인** | **논점 소멸.** 선형모델 전용 기법이므로 쓰지 않는다 (아래 설명은 기록용) |
| **대표변수 선정** | `sub_grade` 단독 vs `int_rate` 단독 | **예측 목적에선 소멸.** 셋 다 넣어도 무해. 변수중요도 해석 시에만 1개로 좁힌다 |
| **공동신청 15개 변수** | 시트·류성환: 제외 ↔ 유명곤: 7.20%(126,357건)나 되니 **챌린저**[^challenger]로 비교 | 남음 (XGBoost면 넣는 쪽으로 기울지만 결정 필요) |
| **희소사건 4개** | 시트·나: 저분산이니 제외 ↔ 유명곤: **자동 제외 금지** | 남음. `num_tl_30dpd` 등, 양수 사건이 777~5,406건 |
| **`Default` 268건** | 유명곤: 주분석 제외 + 민감도 ↔ 류성환: 팀 확정 필요 ↔ 나: 미언급 | 남음 (영향은 미미) |
| **완결표본 건수** | 류성환: 1,115,888 ↔ 유명곤·나: **1,117,571** | 차이 1,683건은 `Does not meet the credit policy.` 접두건. `src/preprocessing/AGENTS.md`가 **포함**으로 규정 → 류성환님 쪽 수정 대상 |

### `X_masked` 공식 문제 — 기록용

전제 1을 확정하면 쓸 일이 없지만, 시트에 남아 있으므로 정정은 해두는 편이 좋다.

시트 원문은 `X_masked = X × D_X`인데, `D_X = 1`이 결측을 뜻한다. 그대로 계산하면:

```
결측인 행 :  NaN × 1  =  NaN
관측된 행 :   X  × 0  =  0     ← 살아있는 값이 전부 0으로 지워짐
```

**살아있는 값을 전부 지우고 결측만 남기는 컬럼**이 된다. 올바른 형태는 `X × (1 − D_X)`다.

### 확정된 전처리 규칙

두 전제와 두 실측을 합치면 결측 처리가 **한 줄로 정리된다.**

```
모든 결측 → NaN 그대로 투입. 대체하지 않고, 더미도 만들지 않는다.
```

| 대상 | 처리 | 근거 |
| --- | --- | --- |
| T2 pre-2016 (미수집) | NaN 그대로 | 더미는 발행연도 대리변수일 뿐 (3절) |
| T2 2016+ (계좌 미보유) | NaN 그대로 | `open_act_il`이 이미 그 정보를 담고 있다 (6절 쟁점 B) |
| T3 (사건 없음) | NaN 그대로 | XGBoost가 분기 방향을 학습 (6절 쟁점 A) |
| 파생 더미 전체 | 만들지 않음 | 네 스킴 AUC 차이가 잡음의 1/15 |

> 전부 다시 필요해지고, 류성환님의 2트랙 구조로 돌아가야 한다.

## 미주 (용어 설명)

[^t2]: **T2 변수** — 결측 원인별 분류(T0~T3) 중 하나로, "2015년 12월부터 수집이 시작돼서 그 이전 대출에는 아예 없는" 14개 변수를 가리킨다. `il_util`, `all_util`, `open_acc_6m`, `total_bal_il` 등 주로 할부계좌·리볼빙 관련 항목이다. 참고로 T0은 결측이 없는 변수, T1은 결측이 드문 일반 변수(0.1~7%), T3는 "사건이 없어서 비어 있는" 변수(예: 연체한 적이 없으면 "마지막 연체 후 경과월"이 빈다)다.

[^dummy]: **결측더미 (D_X, missing indicator)** — "이 값이 비어 있었는가"를 0/1로 기록하는 별도 컬럼. 결측 자체가 정보를 담고 있을 때 그 정보를 모델에 명시적으로 알려주는 장치다. 예: `mths_since_last_delinq`가 비어 있으면 `D = 1`로 표시해 "연체 이력 없음"이라는 사실을 보존한다. 값을 채워버리면 이 정보가 사라지기 때문에 쓴다.

[^split]: **시간순 분할 (temporal split)** — 학습/검증/테스트를 무작위가 아니라 **날짜 순서대로** 나누는 방식. 과거로 학습해 미래를 맞히는 실제 상황을 흉내 낸다. 반대는 **랜덤 분할**로, 전체를 무작위로 섞어 나눈다. 랜덤 분할은 같은 시기 데이터가 학습·검증에 모두 들어가므로 성능이 낙관적으로 나오는 경향이 있다.

[^logit]: **로지스틱 회귀** — 부도확률처럼 0~1 사이 값을 예측하는 가장 기본적인 통계모형. 각 변수에 계수(가중치)를 곱해 더하는 선형 구조라 **해석이 쉽다**는 게 최대 장점이다. 대신 결측치를 그대로 받지 못하고, 변수 간 상관이 높으면 계수가 불안정해진다.

[^xgb]: **XGBoost** — 의사결정나무 여러 개를 순차적으로 쌓아 올리는 방식의 모형(Gradient Boosting). 예측력이 높고, **결측치를 그대로 넣어도 알아서 처리**한다. 각 분기점에서 "빈 값은 왼쪽으로 보낼까 오른쪽으로 보낼까"를 데이터로부터 학습하기 때문이다. 대신 개별 변수의 영향을 해석하기는 어렵다.

[^confound]: **교란 (confounding)** — A와 B가 관련 있어 보이는데, 사실은 숨은 제3의 변수 C가 둘 다에 영향을 준 경우. 여기서는 "T2 결측 여부"와 "부도율"이 관련 있어 보였지만 실제로는 **발행연도**가 둘 다를 움직인 것이었다. 해결책은 C를 고정하고 비교하는 것(**층화**)으로, 본문에서 "2015년만 보면"이라고 한 것이 그 방법이다.

[^cohort]: **코호트 (cohort) / 빈티지 (vintage)** — 같은 시기에 실행된 대출 집단. "2016년 코호트"는 2016년에 나간 대출 전체를 뜻한다. 대출 심사 기준이나 경제 상황이 해마다 달라지므로 코호트가 다르면 부도율도 다르다.

[^median]: **중앙값 대체 (median imputation)** — 빈 값을 그 변수의 중앙값(값을 크기순으로 줄 세웠을 때 한가운데 값)으로 채우는 것. 평균보다 극단값에 덜 흔들려 널리 쓰인다. 다만 "빈 값에도 의미가 있는" 경우에는 그 의미를 지워버린다는 게 6절 쟁점 B의 요지다.

[^singular]: **특이행렬 (singular matrix)** — 완전히 똑같은 컬럼이 여러 개 있거나 한 컬럼이 다른 컬럼들의 조합으로 정확히 만들어지면, 로지스틱 회귀가 계수를 계산하는 과정에서 나눗셈의 분모가 0이 되어 **답이 하나로 정해지지 않는다**. "A와 B의 합이 10"이라는 조건만으로 A와 B를 각각 알 수 없는 것과 같다. 이 경우 모형이 오류를 내거나 터무니없는 계수를 뱉는다. 트리 모형(XGBoost)은 이 문제가 없다.

[^auc]: **AUC (ROC-AUC)** — 모형이 부도 건과 정상 건을 얼마나 잘 구분하는지 나타내는 0.5~1.0 사이 지표. 0.5는 동전 던지기, 1.0은 완벽이다. "무작위로 뽑은 부도 건이 무작위로 뽑은 정상 건보다 높은 위험점수를 받을 확률"로 해석할 수 있다. 우리 모형은 0.62~0.70 수준. **단, 우리 프로젝트의 최종 판단 기준은 AUC가 아니라 Sharpe Ratio다** — AUC는 중간 진단용으로만 쓴다.

[^noise]: **잡음 대비 (signal-to-noise)** — 같은 모형이라도 데이터를 무작위로 뽑을 때마다 AUC가 조금씩 달라진다(난수 시드에 따른 편차). 우리 실험에서 이 자체 편차가 약 0.0015~0.0035였다. 어떤 변화가 "진짜"이려면 이 편차보다 확실히 커야 한다. "잡음의 5.7배"는 시드를 바꿔가며 재도 흔들리지 않을 만큼 확실한 차이라는 뜻이다.

[^oot]: **out-of-time 검증** — 학습에 쓰지 않은 **다른 시기**의 데이터로 성능을 재는 것. 그냥 랜덤하게 떼어놓은 검증셋과 달리, "시간이 흘러도 이 모형이 작동하는가"를 본다. 6절 쟁점 A에서 결측더미가 검증 구간에서 한 번도 켜지지 않은 것을 발견한 방법이다. **분할 규칙과는 별개의 진단 도구**로, 랜덤 분할을 쓰면서도 필요할 때 따로 돌릴 수 있다.

[^maturity]: **만기컷 (maturity filter)** — 만기가 이미 지난 대출만 분석에 쓰는 표본 필터. 각 대출의 `issue_d + term`을 계산해 판정하므로, 36개월과 60개월을 각각 다르게 다룬다. 우리 데이터 스냅샷이 2020-10이고 상각(charge-off) 확정에 통상 4~5개월이 걸리므로, 6개월 버퍼를 더해 `issue_d + term ≤ 2020-04`를 쓴다. 1.2절 참고.

[^seasoning]: **seasoning 편향** — 최근에 나간 대출은 아직 상환 중(`Current`)이라 결과가 확정되지 않았다. 그래서 최근 코호트에서 결과가 확정된 건만 남기면 **조기 완납했거나 조기 부도난 대출**만 과대표집된다. 실제로 만기가 도래한 완결건의 부도율은 16.06%인데 도래하지 않은 완결건은 24.54%로 **8.5%p** 차이가 난다. 이 편향을 막는 것이 만기컷의 목적이다.

[^mono]: **단조변환 (monotone transformation)** — 값의 **크기 순서를 바꾸지 않는** 변환. 로그 씌우기, 상수 곱하기, 상한에서 자르기(캡핑) 등이 여기 속한다. 트리 모형은 "이 값이 기준보다 큰가 작은가"만 보고 분기하므로 단조변환에 결과가 **전혀 변하지 않는다.** 반면 선형모형은 계수가 값의 크기에 직접 곱해지므로 영향을 받는다. 캡핑·로그변환·표준화 논쟁이 모형에 따라 갈리는 근본 이유다.

[^te]: **Target Encoding** — 범주형 변수(예: `addr_state` 50개 주)를 숫자로 바꿀 때, 각 범주의 **평균 부도율**을 그 범주의 값으로 쓰는 기법. 컬럼 수를 늘리지 않아 효율적이지만, 전체 데이터로 평균을 내면 **정답을 미리 보는 누수(leakage)** 가 된다. 그래서 반드시 학습 데이터 내부에서만, 그것도 폴드를 나눠 계산해야 한다.

[^capping]: **캡핑 (capping / winsorization)** — 비정상적으로 큰(또는 작은) 값을 일정 한도에서 잘라내는 것. 예를 들어 `dti`(소득 대비 부채비율) 최댓값이 999인데 이건 실제 비율이 아니라 "값 없음"을 나타내는 코드값일 가능성이 크다. 상한 100을 걸면 999인 행이 100으로 바뀐다. **행을 지우지 않고 값만 조정**한다는 게 이상치 제거와의 차이다. 선형모형에서는 극단값이 계수를 흔들기 때문에 유용하지만, 트리 모형에서는 단조변환이라 효과가 없고 오히려 값을 뭉개 정보를 줄인다.

[^challenger]: **챌린저 (challenger model)** — 현재 채택한 기본안(챔피언)에 도전장을 내는 대안 모형. 두 모형을 같은 데이터로 나란히 돌려 성능을 비교하고, 챌린저가 이기면 교체한다. "이 변수는 규모가 작으니 그냥 빼자"고 단정하는 대신 **넣은 버전과 뺀 버전을 실제로 돌려 비교하자**는 태도다. 금융권 모형 관리에서 표준적으로 쓰는 개념이다.

[^rare]: **희소사건 변수 (rare event variable)** — 값이 0이 아닌 행이 극히 드문 변수. 예를 들어 `num_tl_120dpd_2m`(현재 120일 연체 중인 계좌 수)은 100만 건 중 777건만 0보다 크다. 대부분이 0이라 **분산이 거의 없어** 보통 "저분산 변수"로 제외 대상이 된다. 다만 드물게 발생하는 그 사건이 **매우 강한 위험 신호**일 수 있어서, 자동 제외가 옳은지가 9절의 쟁점이다. (완전히 값이 하나뿐인 상수 변수와는 구분해야 한다.)
