# Lending Club 신용평가모형 & Sharpe Ratio 최적화

서울대학교 핀테크 전문가 과정 "통계, 데이터 사이언스" 과목 팀 프로젝트.

## 프로젝트 개요

**목적:** Lending Club 대출 데이터를 분석해 신용평가모형(부도확률 예측)을 구축하고, 이를 이용한 대출 승인/거절 전략의 **Sharpe Ratio를 극대화**하는 것이 최종 목적이다.

**세부 프로세스:**
1. 전체 데이터를 Train 60% / Validation 20% / Test 20%로 분할한다.
2. **Train**: 부도확률을 예측하는 신용평가모형을 학습한다.
3. **Validation**: 승인/거절 임계점(threshold)을 결정한다 — 기준은 Sharpe Ratio 극대화.
4. **Test**: 확정된 모형과 threshold로 Sharpe Ratio를 검증한다 (재조정하지 않는다).

**Sharpe Ratio 정의:**
```
Sharpe Ratio = (포트폴리오 수익률 − 무위험수익률) / 포트폴리오 수익률의 표준편차
```
- **승인한 대출의 실현수익률 — 재투자 가정 확정** (2026-07-29 회의, `decision_log.md` #18)

  ```
  R = (W/P)^(12/T) − 1,    W = Σ CFm · F(m,T)
  ```
  매달 받는 상환액을 **잔존기간에 맞춘 국채**에 재투자한다고 보고 만기 `T` 시점 종가로 평가한다.
  현금 보유(재투자율 0%)가 아니다. **정상상환·부도 양쪽에 같은 관례를 쓴다.**
  - ⚠️ **"정상상환 시 `int_rate`"는 폐기됐다.** `int_rate`를 그대로 쓰는 것은 재투자율 12.6%를 가정하는 것과 같아 부도 쪽(국채)과 어긋난다. `int_rate`는 **피처로만** 쓴다.
  - **구조는 확정됐다 — A′** (2026-07-30, `decision_log.md` #20): **부도분은 PD 분위(× term)별 그룹 평균**, **정상상환분은 그룹 평균이 아니라 건별 계약 현금흐름**으로 계산한다. 정상상환 수익률은 승인 시점에 거의 결정론적인데(불확실한 건 조기상환 시점뿐) 부도 손실은 데이터에 없는 요인이 지배하므로, 알 수 있는 쪽을 뭉개지 않는다. **구조 B(2단계 hurdle 건별 회귀)는 기각 — 2단계 회귀 모델을 만들지 않는다.**
  - ⚠️ **계산 세부 3건은 미확정**이며 B팀 담당이다(#20): **조기상환 보정 방식**(1순위 — 계약 현금흐름만 쓰면 국채 재투자 가정 아래서 `R`이 과대추정된다), 국채 금리 기준(ⓒ발행시점 고정 권고), 투자자 서비스수수료(~1%). 세 항목은 **잠정값으로 진행 가능**하며 A팀 작업을 막지 않는다.
  - **재투자 가정은 `R`을 무조건 올린다**(`F(m,T) ≥ 1`, 평균 +107.5bp). 다만 편의를 추가하는 게 아니라 0% 관례의 이중 부과를 제거하는 것이다 — `Rf = 2%`일 때 **무위험 등가 대출**(2% 원리금균등, 부도 없음)의 초과수익이 0% 재투자에서 **−0.96%p**(국채와 같은 대출을 거절 판정), 국채 재투자에서 **+0.000%** 로 나온다.
  - ⚠️ **절대 Sharpe를 성과로 보고하지 않는다.** 재투자 가정이 모형 전략과 approve-all 대조군을 똑같이 밀어올리므로, 헤드라인은 **Δ Sharpe = (모형 − approve-all)** 이다. 0% 재투자 결과는 민감도로 병기한다.
  - ⚠️ 옛 문서의 "부도 시 0"은 **회수액이 0**이라는 뜻의 축약 표기다. 수익률로는 **-100%** — 수익률 0%(= 원금은 전액 회수, 이자만 손실)와 혼동하지 말 것. -100%는 이제 베이스라인도 아니다.
- 거절한 대출: 무위험수익률로 대체 — **발행시점(`issue_d`)에 대출 만기와 만기를 맞춘 미국채**(`GS3`/`GS5`)에 투자했다고 가정한다 (#18 확정).

## 데이터 전처리 유의사항

### 독립변수(피처) 구성
- 대출 발생 **전** 시점에 확정되는 변수만 써야 한다. 단, `grade`·`sub_grade`·`int_rate`·`installment`·`funded_amnt`·`funded_amnt_inv`·`issue_d`·`initial_list_status`처럼 대출 **발행(origination) 시점에 함께 확정**되는 값은 신규 심사 대상 데이터에도 이미 채워져 들어오므로 사전 변수로 간주한다 (조교님 확인: 신규 데이터 컬럼이 훈련 데이터와 동일). 반면 `total_pymnt`·`recoveries`·`hardship_status`처럼 대출 실행 후 **시간이 지나야** 값이 생기는 상환/연체/구제 이력은 여전히 사후 변수라 제외 대상.
- 범주형 변수는 더미화하되, 의미 없는 범주는 제외한다 (전부 더미화하면 변수 수가 폭증해 모델 설명력이 떨어짐).
- **결측 처리는 "전부 NaN 그대로 투입"으로 확정됐다** (`decision_log.md` #13 ③·#17, 2026-07-29 회의). 대체하지 않고 더미도 만들지 않는다. XGBoost가 결측을 직접 다루기 때문이며, 처리 스킴 4종의 AUC 차이가 seed 편차의 1/15로 구분 불가였다.
  - ⚠️ 아래 마스킹 기법은 **로지스틱 회귀를 전제로 한 과거 검토**다. 모형이 XGBoost로 단일화되면서(#17 ①) 필요 없어졌다. 배경으로만 읽는다.
  - (과거 기록) 변수 `X`에 결측 여부 더미 `D_X`를 만들고 `X_masked`를 함께 넣으면 "데이터가 없다는 사실 자체의 효과"와 "관측된 X값의 실제 효과"를 분리해 추정할 수 있다 (류근관 교수님 추천 기법). 단 **공식은 `X × (1 − D_X)`가 맞다** — `D_X = 1`이 결측을 뜻하는데 `X × D_X`로 쓰면 살아있는 값이 전부 0으로 지워진다.
  - 예: `mths_since_last_record`는 결측 자체가 "부정적 신용 사건이 없었다"는 긍정적 신호일 수 있음 — 무작정 대체/삭제하면 안 됨. 이 정보는 NaN을 그대로 넣어도 트리가 분기 방향으로 학습한다.
- 단위를 맞춘 파생(비율) 변수가 필요하다. 예: `revol_bal`(리볼빙 잔액)은 절대금액보다 신용한도 대비 비율로 봐야 신용도 해석이 맞다 — 모델은 변수 크기 자체에 가중치를 매기기 때문에 원본 그대로 쓰면 왜곡될 수 있다.

### 샘플링(행 필터링) 확정 사항
- **`Current`는 제외한다** — 우측중도절단 자료(결과 미확정)라서 (교수님 확정 지침). 대안으로 "대출금 대비 상환금액" 비율을 타겟으로 잡으면 `Current`도 포함 가능하다는 아이디어가 있었으나, 최종적으로는 제외로 확정됨.
- **`Late` 데이터는 제외한다** — Late→Fully Paid/Charged Off 전이율 계산을 시도했으나 표본이 전체의 1% 미만이라 포기.
- `Does not meet the credit policy. Status:*`는 관례적으로 뒤에 붙은 `Fully Paid`/`Charged Off`와 동일하게 취급 (공식 정의 불명확, 유의).

## 데이터 분석 유의사항

### 대출 간 독립성 문제
경기 상황에 따라 전체 대출의 부도 확률이 동조화될 수 있어, 대출들이 서로 독립이라는 가정이 깨질 수 있다.
- 대응 방안 1: 실업률/GDP성장률/기준금리/물가지수 같은 거시경제 변수를 피처로 추가.
  - **진행**: 실업률·신규 실업수당청구·10y-2y 금리차·CPI 4종 수집 완료(2026-07-26).
    다만 대출 표본에 붙여보니 4종 모두 이론과 반대 부호가 나왔고, 원인은 거시지표가
    발행연도의 대리변수가 되는 교란(`corr(실업률, 발행연도) = -0.911`)으로 확인됐다.
    **→ 2026-07-29 회의에서 미사용으로 확정**(`decision_log.md` #15). 원인이 지표가 아니라
    표본 기간이 회복 일변도라는 구조적 한계여서 통계적 처리로 해소되지 않는다. 수집 자료는
    보존하고 보고서에 "시도했으나 채택하지 않은 이유"로 싣는다. 근거는
    `outputs/reports/macro_indicator_selection.md`.
- 대응 방안 2: 개별 부도확률(θᵢ)이 공통 배경요인(λ)에 함께 영향받는 **계층적 베이지안 모형** 구조로 접근.

### Sharpe Ratio 계산 방법론
- `Rf`(무위험수익률)는 미국채 금리로 설정 (교수님 지침). **2026-07-29 회의에서 참고논문 방식 확정** (`decision_log.md` #18) — 대출 **발행시점(`issue_d`)에 대출 만기(36/60개월)와 만기를 맞춘 미국채**(`GS3`/`GS5`)에 투자했다고 가정한다. 고정 상수가 아니므로 `config/config.yaml`의 `risk_free_rate.value`는 `null`을 유지하고 매칭 로직으로 처리한다.
- ⚠️ **우리 지표는 시계열 Sharpe가 아니다.** 일별 수익률 시계열의 변동성을 재는 게 아니라,
  **대출 간 횡단면 분포**(각 대출의 계약만기 등가 연율화 실현수익률 `R`)에서 평균과 표준편차를 잡는다.
  따라서 다음 두 가지가 **적용되지 않는다**:
  - **√252 연율화** — 일별 관측이 아니므로 제곱근 법칙을 쓸 자리가 없다. 연율화는 이미 `R` 정의
    안에서 `(W/P)^(12/T) − 1` 로 끝나 있다.
  - **"1 이상 양호, 2 이상 우수" 같은 일반 벤치마크** — 스케일이 다른 지표라 비교 대상이 아니다.
- 이 프로젝트에서 기대되는 값은 **0.2~0.4대**라고 조교님이 언급했다. 보고서에는 일반 벤치마크와
  스케일이 다르다는 점을 반드시 함께 적는다.
- 포트폴리오(대출) 수익률은 정규분포가 아니다 — 조금씩 오르다 급락하는 패턴(좌측 꼬리가 긴 분포)이 일반적.
- **사전적 샤프비율 vs 사후적 샤프비율 구분이 핵심.** 사전적 = 미래 기대수익률/표준오차 기반(예측이 목적), 사후적 = 과거 실제수익률 기반(평가가 목적). **이 프로젝트의 최종 목적은 사전적 샤프비율**(신용평가모형으로 미래를 예측하는 것)이다.
- 샤프비율과 신용평가모형의 연결고리: 주식의 리스크는 시장가격 변동, 대출의 리스크는 채무불이행. 대출 수익률은 부도 여부(베르누이 확률변수)로 결정되므로 그 평균/표준편차 모두 부도확률 p의 함수 → p를 추정하는 도구가 신용평가모형.

### Threshold 확정 방법 — 반복 재표본 방식 (**K=50회로 확정**, `decision_log.md` #18)
Validation 표본 하나로 계산한 Sharpe Ratio는 "진짜 성과"가 아니라 표본에 따라 흔들리는 추정치다. 대출 수익률은 부도 여부(베르누이 확률변수)로 결정되므로, 어떤 대출이 우연히 Validation에 뽑혔느냐에 따라 평균수익률·표준편차·Sharpe가 크게 달라질 수 있다 (수업 중 언급된 내용).

- **방법**: Test set은 그대로 고정해두고, 남은 Train+Validation 풀에서 매번 다른 방식으로 Train/Validation을 재분할해 모형 학습 → threshold 탐색을 **K=50회** 반복한다(참고논문 선례: `τ*` 범위 0.00~0.15, 평균 0.068, 표준편차 0.041). 표본이 72만 건이라 K가 커지면 학습 시간이 선형으로 늘어나므로, 필요 시 최종 확정본만 더 돌린다. 그러면 반복 횟수만큼의 (threshold, Sharpe) 쌍이 나오고, 이 threshold들의 분포에서 평균 또는 중앙값(비정규분포이므로 중앙값이 더 안정적일 수 있음)을 최종 threshold로 사용하는 방식이다.
- 이미 있는 "30-seed 안정성 검증"(`src/analysis/AGENTS.md`)과는 목적이 다르다 — 그건 threshold 확정 **후** 사후 안정성 점검용이고, 이건 threshold를 **처음 정하는** 단계에서 표본 변동성을 줄이려는 아이디어다.
- 주의: "평균 Sharpe와 비슷한 결과를 낸 threshold 하나를 골라 쓰는" 방식보다, "반복에서 나온 threshold 값 자체의 평균/중앙값"을 쓰는 게 더 안정적이다 (threshold→Sharpe 매핑이 1:1이 아니기 때문).
- **채택 확정**(#18). 반복 방식(재분할 vs 부트스트랩)의 세부는 구현 단계에서 정한다.

### 대출 건별 IRR 계산 고려 (심화 방법)
⚠️ **이 절은 2026-07-29 회의 이전의 검토 기록이다.** 재투자 가정이 확정되면서(#18) "정상 상환이면 `int_rate`"는 폐기됐고, 실현수익률은 `R = (W/P)^(12/T) − 1`로 계산한다. 아래는 그 배경으로 읽는다.

단순히 "부도면 -100%(원금 전액 손실), 정상 상환이면 `int_rate`"로 실현수익률을 근사하는 대신, 실제 상환 현금흐름(월별 상환, 조기상환, 부도 후 일부 회수 등 정확한 시점까지 반영)을 이용해 대출 건별로 실제 IRR을 계산할 수 있다. 단, 이는 신규 대출의 미래를 예측하는 데 쓰이는 게 아니다 — 미래 시점엔 현금흐름 자체가 아직 존재하지 않아 계산이 불가능하기 때문. 대신 **이미 결과가 확정된 Validation/Test 데이터에 적용**해서, ① Sharpe Ratio를 최대화하는 threshold를 더 정확히 선택하고, ② 최종 전략의 성과(Sharpe Ratio)를 더 정확하게 측정·보고하는 데 활용한다.

### 모델 선택 — **XGBoost 단일화로 확정** (`decision_log.md` #17 ①)

2026-07-29 회의에서 **XGBoost 하나로 확정**됐고 로지스틱 회귀는 폐기됐다. 대조군으로 **전부 승인(approve-all)** 전략과 비교한다(#17 ②). 아래는 확정 이전의 후보 검토 기록이다.

(과거 기록) 아직 어떤 모델을 쓸지 확정되지 않은 상태다. Logistic Regression과 Support Vector Machine 모두 후보 모델로 검토 대상이다 (SVM은 류근관 교수님 추천). 특히 SVM은 기본적으로 클래스만 출력하고 확률을 직접 주지 않으므로, Sharpe Ratio 기준 threshold 최적화에 쓰려면 확률로 변환하는 보정(예: Platt scaling)이 추가로 필요할 수 있다는 점을 고려해야 한다. 최종 모델은 특정 후보를 미리 정해두지 않고, Validation/Test 성능(=달성한 Sharpe Ratio)을 비교해서 결정한다.

### 류근관 교수님
- **Accuracy는 중요한 지표가 아니다.** Type 1 오류와 Type 2 오류의 비용이 다른데 accuracy는 이를 동일하게 취급한다. "절대 다루지 마라. 무의미한 얘기다."
- Recall이나 Precision을 극대화하는 것도 중요하지 않다. 결과는 샤프 비율을 극대화하는 것 — 상식에 맞게 모델을 만들 것.
- Missing data 처리 방식도 포인트. 이는 model selection의 문제이며, Validation/Test 성능으로 판단하면 된다.
  - 유용한 기법: 변수 `X_j`의 결측 여부를 나타내는 더미 `D_j`를 만들고, `D_j`와 `X_j*D_j`를 함께 고려한다. 그러면 데이터가 있는 경우/없는 경우의 부도확률을 각각 해석할 수 있고, 데이터 있는 경우끼리만 비교도 가능하다. 제멋대로 버리거나 고르는 것보다 낫다. 결측치가 많아도 유효한 테크닉이다.
- 다중공선성이 있으면 일단 버리고 분석하려 하지만, 무조건 버리는 게 능사는 아니다. 예측의 문제와 계수추정의 문제는 다르다 — 변수 간 다중공선성이 있어도 예측 성능은 좋을 수 있다. "목적이 수단을 정당화한다": 고객(팀)의 목적에 맞는 수단을 쓰면 된다.

### 류근관 교수님 & 류현우 조교님 (Lending Club 설명, 녹음)
